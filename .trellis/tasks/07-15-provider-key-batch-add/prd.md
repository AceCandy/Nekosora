# provider 密钥:批量添加与保存时去重锚定

## Goal

在「编辑服务商」弹窗的 API 密钥区,新增「批量添加」入口(多行 textarea 按行导入);并在保存时对所有密钥统一查重,发现重复则阻止本次保存、滚动并高亮到第一个重复行。

## Background

- 现状:`KeyBundleEditor`(`src/features/providers/KeyBundleEditor.tsx`)只能逐条「+ 添加一个 API 密钥」,一次一个 key + 权重。批量粘贴多个 key 要点很多次。
- 现状**无任何重复检测**:同一条 key 可被重复加入并保存,使加权负载均衡 bundle 里出现重复条目,无意义且易混淆。
- 现状保存(`ProviderFormDialog` 的 form submit)无客户端预校验,直接进 server action。
- 重复判定基准:trim 后的精确字符串匹配,忽略空行,区分大小写。

## Requirements

### R1:批量添加入口与弹窗

- 在「+ 添加一个 API 密钥」旁新增「批量添加」按钮,点击弹出 Modal。
- Modal 内为一个多行 textarea + 确认/取消。
- 确认提交的处理:按 `\n` 拆行 → 每行 `.trim()` → 丢弃空行 → **批次内部**去重(保留首次出现)→ 每行权重默认 `1` → **追加**到现有密钥行列表末尾。
- 批量添加的每行只承载密钥本身,不支持单独指定权重(权重统一为 `1`)。
- 批次内全部为空行 / 无有效内容时,不新增行,也不报错。

### R2:保存时统一重复检测(单条 / 批量两条路径共用)

- 点「保存」时,对所有非空密钥行(trim 后)做整体查重,**不区分**该行是单条加的还是批量加的。
- 发现重复时:
  - **阻止本次保存**(不发起保存请求)。
  - 自动滚动到「第一个重复行」并高亮数秒。
  - 提示「第 N 行与第 M 行密钥重复」(定位到具体行号,便于用户处理)。
- 不重复时正常进入原有保存流程。

### 范围排除

- 不改密钥的加密 / 解密、加权选择、探测(probe)逻辑。
- 不改 provider 的其它字段(名称 / 协议 / 接口地址 / 轮询策略等)。
- 批量添加**不**引入「与已有列表查重并静默剔除」的语义(被否决的方案);与已有列表的重复统一交给保存时检测处理。

## Acceptance Criteria

- [ ] 「+ 添加一个 API 密钥」旁出现「批量添加」按钮,点击弹出多行 textarea Modal。
- [ ] 批量提交:按行 trim、丢空行、批次内去重、权重=1,正确追加到列表末尾;批次内有重复时只保留一份,不报错。
- [ ] 批次内全部为空行或无有效内容时,不新增行,不报错。
- [ ] 点保存时,若列表存在重复密钥:阻止保存、滚动并高亮到第一个重复行、提示具体重复行号。
- [ ] 重复判定为 trim 后精确匹配、区分大小写;前导/尾随空格不同的两条视为重复。
- [ ] 无重复时保存流程与改动前完全一致。
- [ ] `pnpm typecheck` 0 错;相关既有测试全过;中英文 i18n 文案齐全。
- [ ] 暗色模式下 Modal 与高亮样式正常。

## Open Questions

- 无。方案已定:① 保存时统一检测;② 批量仅密钥、权重默认 1;③ 重复则阻止保存 + 滚动高亮到第一个重复行;重复判定为 trim 后精确匹配、忽略空行、区分大小写。
