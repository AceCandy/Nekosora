# 统一拖拽排序控件

## Goal

统一所有现有可排序列表的操作方式，减少重复控件，并让长列表中的条目可以直接移到顶部。

## Background

- 当前共有四处可拖拽排序列表：模型、输出模式、渲染样式、Web 搜索后端。
- 输出模式和渲染样式同时显示拖拽、上移、下移；模型和 Web 搜索仅显示拖拽，视觉与行为不一致。
- 模型和 Web 搜索支持键盘拖拽，输出模式和渲染样式目前仅注册指针拖拽。
- 项目已有统一的拖拽排序落库契约，可直接复用现有乐观更新和 reorder action。

## Requirements

- 四处列表统一使用相同的拖拽手柄视觉、尺寸、触屏热区、焦点态、禁用态和拖动反馈。
- 排序控制只保留拖拽手柄和一个“移到顶部”操作，不再提供逐项上移或下移。
- “移到顶部”将当前条目一次移动到列表索引 0，并沿用该列表现有的乐观更新与持久化排序链路。
- 第一项不显示可用的“移到顶部”操作，且各行内容保持对齐。
- 四处列表都支持鼠标、触控和键盘拖拽；键盘用户可聚焦手柄后用 Space 与方向键完成排序。
- 删除本次改动产生的无用移动函数、props、图标导入和中英文上移/下移文案。
- 保留各列表原有的排序范围、鉴权、保存反馈、错误处理和其他行操作。

## Out of Scope

- 新增持久化的置顶/取消置顶状态、字段或分组。
- 修改排序接口、数据库结构或排序业务规则。
- 重设计列表列结构、编辑/删除/启停等非排序操作。

## Acceptance Criteria

- [x] 模型、输出模式、渲染样式和 Web 搜索后端使用一致的拖拽与“移到顶部”控件，不再显示上移/下移。
- [x] 任意非首项可直接移到第一位并通过现有排序链路保存；首项没有可执行的“移到顶部”操作。
- [x] 四处列表均可使用鼠标、触控和键盘完成排序，排序期间正确处理 pending/disabled 状态。
- [x] 中英文操作名称完整且没有遗留的上移/下移引用。
- [x] 相关组件测试、lint、typecheck 和 Next.js 构建通过。

## Notes

- 本任务不改变后端契约，采用 PRD-only 轻量流程。
- “移到顶部”是一次性重排操作，不等同于聊天会话的持续性“置顶/取消置顶”。
