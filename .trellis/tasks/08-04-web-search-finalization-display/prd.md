# 联网搜索工具轮耗尽后的最终总结与逐调用展示

## Goal

确保 WebChat 在工具调用轮数耗尽后仍能基于已有工具结果生成一次最终回答，并让每条 `web_search` 调用准确显示自己的搜索后端或失败原因。

## Background

- 当前 Agent loop 默认最多执行 5 轮；若第 5 轮仍返回工具调用，工具执行完成后不会再请求模型总结，外层会把自然 EOF 标记为 `interrupted` 并显示“生成未正常完成”。
- 搜索参数校验失败只返回 `invalid_search_query`，模型无法直接得知冲突字段，容易重复消耗工具轮次。
- 前端把搜索后端聚合在消息级 `searchBackends`，并只显示在第一条 `web_search` 上，无法表达逐调用来源；失败调用还可能错误继承后续成功调用的后端。

## Requirements

- 保留现有最多 5 个工具调用轮次；只有达到上限且最后一轮仍执行了工具时，额外发起一次禁用所有工具的最终总结请求。
- 最终总结最多执行一次，不得再次调用或重复执行工具。
- 最终总结复用已有消息、工具调用与工具结果；其文本、推理、用量和最终 `finish` 继续走现有流式契约。
- 最终总结成功才使整轮成功；失败、异常或取消保持现有 failed/interrupted 语义，不伪造 `finish`。
- 无工具请求和未耗尽工具轮次的现有行为不变。
- 搜索参数校验失败结果包含稳定错误码和可操作的安全提示，但不暴露内部异常或原始校验对象。
- 每条搜索调用通过 `toolCallId` 绑定自己的成功后端或失败原因；不得把消息级聚合后端错误显示到其他调用。
- 流式消息与刷新后的历史消息展示一致。
- 复用现有 `processTrace.webSearch.calls` 和 `tool_calls.tool_call_id`，不新增数据库字段或迁移。

## Acceptance Criteria

- [x] 连续 5 个工具轮次耗尽后只增加 1 次不含 `tools` 的最终请求，并能生成最终正文与唯一 `finish`。
- [x] 强制总结请求不能产生新工具调用，也不能重复执行前 5 轮工具。
- [x] 强制总结失败或取消时保留已有正文、工具记录和引用，并写入正确终态。
- [x] 工具调用在 5 轮内自然结束时不增加额外请求。
- [x] `freshness` 与日期范围冲突时，工具结果明确提示两者互斥。
- [x] 多条 `web_search` 分别显示各自后端；参数校验失败的调用显示失败原因且不显示未实际调用的后端。
- [x] 历史恢复后逐调用后端与失败原因不串行、不丢失。
- [x] 搜索引用仍按现有 URL 规则聚合，搜索后端聚合字段保持兼容。
- [x] Agent loop、coordinator、SSE/store、历史投影和组件定向测试通过。
- [x] `pnpm check`、完整测试和 `git diff --check` 通过。

## Out of Scope

- 不提高或配置化现有 5 轮上限。
- 不改变公开 `/v1/*` 接口的工具循环。
- 不修改搜索供应商选择、排序或缓存策略。
- 不新增工具调用审计字段或数据库迁移。
