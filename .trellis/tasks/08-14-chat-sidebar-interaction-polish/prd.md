# Chat 侧栏交互与研究状态修复

## Goal

让会话数量增长和多状态切换时，Chat 侧栏仍能稳定定位、明确反馈且适合键盘与移动端操作；同时保证“研究完成”只在搜索与准备工作真正结束、正文即将开始时出现。

## Background

- 当前会话查询使用全局 30 条键集窗口，分组仅在客户端对已加载项目分类，因此尚未加载到的“更早/归档”等分组标题不可见，加载更多按钮也只能出现在整个列表底部。
- `renameConversation` Server Action 已存在，但 Sidebar 未暴露重命名入口；归档项已有“取消归档”，但操作菜单的定位和可见性降低了可发现性。
- 会话操作菜单使用滚动容器内的 `absolute top-full`，底部空间不足时会向下扩展 scroll height，而不是向上翻转。
- 更多操作按钮只通过 `group-hover:opacity-100` 显示，键盘聚焦时可能保持透明。
- 侧栏生成状态使用小型 `Loader2` 旋转图标，实际反馈不够明显；离线 Server Action 也缺少客户端超时和明确错误反馈。
- 移动端由 Sidebar 额外渲染“菜单 + Logo”首行，ChatHeader 再渲染标题/样式/分享第二行，造成标题层级后移。
- `buildResearchStatus` 只用总体 phase 判定完成；当 phase 已前移但 `web_search` 仍为 `calling/running` 时，会过早显示“研究完成”。

## Requirements

- R1. 所有非空会话分组标题必须始终可见并展示真实总数；每组每次最多加载 20 条，超出时只在该组内部继续加载。首屏 RSC 仍沿用全局最多 30 条，不能退回全量会话序列化；“更早”和“归档”默认折叠且首次展开时才加载，但当前会话位于尚未加载的分组时必须例外补入并保持可见。
- R2. 侧栏提供重命名、置顶/取消置顶、归档/恢复和删除入口；置顶、取消置顶、归档、恢复或重命名导致列表重排后，滚动容器必须自动定位当前会话。
- R3. 会话操作菜单使用脱离滚动容器的浮层定位和碰撞检测；底部空间不足时向上展示，不增加列表 scroll height。
- R4. 更多操作按钮在 hover、菜单展开和键盘 focus/focus-within 时均可见，焦点指示满足现有 WCAG/设计 token 约束。
- R5. 生成中状态在正常动效与 reduced-motion 下都可明确识别；不能仅依赖难以感知的旋转缺口。
- R6. 加载更多点击后立即显示稳定 pending 状态；离线、网络失败或超时后进入明确可重试状态，不清空已有会话。
- R7. 移动端移除独立 Logo 行，菜单按钮与 Chat 标题、输出样式和分享入口处于同一首行；桌面布局保持现状。
- R8. 只要任一研究步骤或 `web_search` 调用仍为 running/calling，整体状态就不能显示“研究完成”；完成状态必须同时满足研究步骤终止以及即将输出/已输出首个正文内容。
- R9. 保持现有亮色主题、消息搜索独立查询、聊天正文滚动、custom renderer 与 Markdown 加载边界不变。

## Acceptance Criteria

- [ ] 分组标题与实际总数一致，首屏合计不超过 30 条；每组每页不超过 20 条，任一分组有后续页时只在该组显示加载更多，重复点击、失败重试和末页无重复/漏项。
- [ ] “更早”和“归档”默认折叠且标题仍可见，首次展开时加载本组；当前会话位于折叠或未加载分组时仍被补入、可见并高亮。
- [ ] 重命名、置顶、取消置顶、归档、恢复、删除均可从菜单完成；重排后当前会话仍可见并保持高亮。
- [ ] 底部会话菜单自动向上翻转且不改变滚动条长度；鼠标和键盘均能打开、操作并关闭菜单。
- [ ] 更多操作按钮获得键盘焦点时可见；所有新增控件有明确 focus-visible、disabled、loading 和 error 状态。
- [ ] 生成中标识清晰可辨；离线加载会即时进入反馈状态并在失败/超时后显示可操作的重试入口。
- [ ] 390px 下菜单按钮、会话标题、输出样式和分享位于同一首行，无 Logo 占位、横向溢出或控件遮挡。
- [ ] 搜索仍在运行时标题保持“正在搜索/阅读”，所有研究步骤结束且进入正文边界后才显示“研究完成”；流式与历史恢复一致。
- [ ] 定向测试、`pnpm check`、`pnpm test`、Web 生产构建及登录态桌面/390px 浏览器回归通过。

## Out Of Scope

- 恢复暗色主题或调整聊天正文滚动模型。
- 引入 React Query/SWR 或为会话列表增加虚拟滚动。
- 修改联网搜索后端策略、来源排序或内容质量。
- 处理登录按钮的既有对比度问题。
