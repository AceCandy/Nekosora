# 修正设置页加载与交互反馈

## Goal

让设置中心切换时立即提供可感知的加载反馈，并修正长期记忆仍有明显等待、指令卡信息层级杂乱和“返回聊天”入口指引不足的问题。

## Background

- 上一任务 `08-26-admin-settings-experience` 把 `getMemories()` 的过期清理移入 60 秒缓存未命中回调，保证缓存命中零 Mem0 调用；该单元级优化没有证明从点击长期记忆 Tab 到页面可交互的端到端耗时改善。
- `(dash)/template.tsx` 当前只在新页面挂载后执行 200ms 淡入/轻微位移；服务端取数期间没有可见反馈，因此用户几乎感知不到。
- 指令卡当前结构化渲染完整 Markdown；用户明确要求取消正文展示，以视觉层级和整洁度为主。
- “返回聊天”当前只有 hover、键盘焦点与按下状态位移；用户要求静止状态也能周期性提示可点击。
- 浏览器实测（本地开发服务、18 条记忆）：首次进入内容出现约 225ms，RSC 136ms、TTFB 23.5ms；再次进入内容出现约 260ms，RSC 110ms、TTFB 23.5ms。当前 200ms template 动画在内容返回后才开始，视觉稳定时间约 425–460ms。证据表明 Mem0/服务端不是本轮主要慢点。

## Requirements

- R1：测量长期记忆从点击导航到内容可交互的完整链路，区分客户端导航等待、鉴权、缓存访问、Mem0 首次读取与服务端渲染；按证据修复真实主要慢点，不能只以 `getAll` 调用次数作为性能结论。
- R2：指令卡不再展示 Markdown 正文或正文摘要；保留标题、触发词、描述、使用次数、编辑和删除，并重新整理为紧凑、清晰的卡片。
- R3：设置/管理页面导航后，在服务端页面尚未返回时立即显示与 Chat 会话切换一致或同类的内容骨架反馈；现有“完成后才入场”的 200ms template 动画应移除或不再作为主反馈。
- R4：“返回聊天”箭头在无交互时也以克制的周期性位移动效提示可点击；hover、键盘焦点、active 反馈继续保留，减弱动效时停止自主运动。
- R5：不新增动画或数据请求依赖，不改变记忆 CRUD、指令卡 CRUD、导航 URL 或权限边界。

## Acceptance Criteria

- [ ] AC1：保留修改前后的端到端实测数据；长期记忆导航期间立即出现加载反馈，内容返回后不再追加 200ms 入场等待。
- [ ] AC2：指令卡不渲染正文 Markdown，卡片在桌面和 390px 下无横向溢出，编辑、删除、触发词和使用次数保持可用。
- [ ] AC3：点击设置左侧导航后，目标内容返回前立即出现内容区加载反馈；反馈不遮挡侧栏，不导致布局跳动。
- [ ] AC4：返回聊天入口静止时可观察到周期性箭头提示，hover/键盘焦点反馈清晰；`prefers-reduced-motion` 下自主运动关闭。
- [ ] AC5：相关单测、Web lint/typecheck 通过；浏览器覆盖桌面、390px、键盘和减弱动效。

## Out of Scope

- 不重做长期记忆页面信息架构或 Mem0 存储模型。
- 不给指令卡增加新的预览模式、展开正文或 Markdown 编辑器。
- 不引入全局进度条、动画库或跨路由状态管理。
