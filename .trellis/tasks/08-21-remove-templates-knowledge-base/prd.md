# 彻底删除提示词模板和知识库

## Goal

在产品尚未上线、无需兼容既有用户数据的前提下，彻底移除提示词模板和知识库能力，减少无用产品入口与维护成本，同时保留指令卡、普通文件上传和聊天附件能力。

## Background

- 用户确认两项能力尚未上线，可以彻底删除，无需采用仅隐藏入口的可回滚下线方案。
- 提示词模板当前横跨后台/用户页面、模板服务、聊天请求字段、聊天上下文装配、数据库表和内置种子数据。
- 知识库当前横跨管理页面、文件分组与检索服务、聊天选择器、RAG 上下文装配、数据库表及文件关联字段。
- 指令卡不在删除范围内。

## Requirements

- 删除提示词模板的所有前端入口、交互、服务、聊天请求字段、运行时装配、种子数据、数据库定义与相关测试。
- 删除知识库的所有前端入口、交互、服务、聊天请求字段、运行时装配、检索调试接口、数据库定义、文件关联字段与相关测试。
- 清理由上述删除产生的无用导入、类型、缓存键、文案和导出，不顺带重构无关代码。
- 保留指令卡完整行为。
- 保留普通文件上传、聊天附件及不依赖知识库分组的文件 RAG 行为。
- 通过新的 PostgreSQL 前向迁移删除相关表、字段，并清理 `conversations.composer_state` 中遗留的 `kbIds`；Drizzle journal/snapshot/schema 必须保持一致。
- 遵守项目迁移不可变契约：不改写已发布的 `0000_baseline.sql`、`meta/0000_snapshot.json` 或既有 journal 条目。

## Acceptance Criteria

- [x] 后台、用户面板和聊天界面不再展示提示词模板或知识库入口与选择器。
- [x] 聊天 API、客户端状态和核心编排不再接受或处理 `templateId`、`templateVars`、`knowledgeBaseIds`。
- [x] 提示词模板及知识库的专属服务、接口、种子数据、类型、文案和测试已删除。
- [x] 当前数据库 schema 不再包含 `prompt_templates`、`knowledge_bases` 及 `file_objects.knowledge_base_id`；新增迁移可从现有基线收敛到该结构，journal 与新 snapshot 连续一致。
- [x] `conversations.composer_state` 不再读写 `kbIds`，前向迁移清除已有 JSON 中该键。
- [x] 指令卡仍可选择并注入聊天 system prompt。
- [x] 普通文件上传、聊天附件和基于附件文件的上下文构建仍保留。
- [x] 相关定向 lint、类型检查或测试通过；若受环境限制未执行，明确记录未验证项与风险。

## Out of Scope

- 重设计或增强指令卡。
- 重构通用聊天、文件存储或 RAG 架构。
- 删除普通文件上传、聊天附件或文件级 RAG。
- 为尚未上线的数据提供导出、归档或兼容读取。
- 改写或压缩已有数据库迁移历史。

## Technical Notes

- `packages/core/src/lib/chat/orchestrator.ts` 同时承载指令卡、普通附件/RAG 与待删除能力，只能局部删除模板和知识库分支。
- 普通附件继续通过文件 ID 进入既有上下文构建；只删除“知识库 ID → 文件 ID”的分组解析。
- `PG_BASELINE_TABLES` 描述既有 `0000` 基线的收养契约，必须继续保留历史表名，不能因前向删除而同步删项。
- 会话 Composer 的完整快照需从七类选择收敛为六类，删除 `kbIds` 但保留 latest-only 持久化语义。
