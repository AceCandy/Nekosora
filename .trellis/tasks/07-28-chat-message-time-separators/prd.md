# 聊天消息时间分隔展示

## Goal

在 Chat 正文与公开分享页中按访问者本地自然日展示克制的消息时间分隔，帮助用户识别跨日对话，同时不改变消息正文、消息顺序、模型上下文或会话业务语义。

## Background

- Chat 当前有序渲染可见分支消息，但前端 `ChatMessage` DTO 尚未携带数据库已有的 `createdAt`。
- 分享页支持实时与快照等现有模式，但公开消息 DTO 和快照 JSON 尚未保留消息时间戳。
- 时间标签需要基于访问者浏览器的本地时区计算，不能在服务端按固定时区预先格式化。

## Requirements

1. 时间分隔只属于展示层，不保存为消息，不发送给模型，也不改变消息内容、顺序、删除、分支或流式行为。
2. 判断范围是同一会话当前展示的有序消息列表：
   - 第一条消息发生在访问者的今天时，不显示时间。
   - 第一条消息早于访问者的今天时，显示时间。
   - 后续消息与紧邻的上一条消息属于同一本地自然日时，不显示时间。
   - 后续消息与紧邻的上一条消息不属于同一本地自然日时，显示时间；即使只跨零点一分钟也必须显示。
   - 同一本地自然日内无论间隔多久，都不额外显示时间。
3. 时间标签按访问时的本地日期和本地时区动态格式化：
   - 今天：`HH:mm`
   - 昨天：`昨天 HH:mm`
   - 前天：`前天 HH:mm`
   - 今年更早：`M月D日 HH:mm`
   - 非今年：`YYYY年M月D日 HH:mm`
   - 英文界面使用对应的本地化表达，不在英文界面硬编码中文。
4. Chat 正文与公开分享页复用同一套日期判断、格式化和分隔展示规则。
5. 同一个公开分享链接按访问者的本地时区与访问日期计算，因此不同时区或不同日期访问时允许显示不同分组。
6. 使用消息的绝对创建时间作为数据源；扩展展示 DTO 与分享快照数据只为呈现时间，不改变会话或模型请求语义。
7. 新创建的快照分享必须保留每条消息的绝对创建时间；实时分享必须从当前可见消息读取创建时间。
8. 客户端新发送的用户消息与生成中的 assistant 占位消息必须具有可用于即时展示的创建时间，刷新后由持久化时间继续驱动展示。

## Compatibility

- 新增时间字段应兼容缺少该字段的既有数据，不得使旧分享页报错或阻断消息正文展示。
- 功能上线前创建的旧快照分享没有消息时间戳时，继续正常显示消息正文，但不显示时间分隔。
- 旧快照不得从当前数据库消息回查时间，避免原会话删除、编辑或分支变化破坏快照的独立性。

## Acceptance Criteria

- [ ] 今天创建并在今天查看的会话，第一条消息前没有时间标签。
- [ ] 第二天再次查看该会话时，第一条消息前显示本地化的“昨天 + 时分”。
- [ ] 第一条消息为前天、今年更早或往年时，分别按约定格式显示。
- [ ] 相邻消息处于同一本地自然日时不显示额外标签，跨本地自然日时在后一条消息前显示。
- [ ] 从昨天跨到今天的后一条消息显示 `HH:mm`，不带“今天”。
- [ ] Chat 正文和分享页对同一消息序列采用相同规则。
- [ ] 分享页按访问者本地时区计算；同一绝对时间在不同时区允许形成不同自然日分组。
- [ ] 时间标签不出现在消息正文、模型请求、复制正文或会话持久化消息内容中。
- [ ] 流式发送、分支切换、消息删除和现有分享正文渲染保持原行为。
- [ ] 缺失或无效时间戳时消息正文仍正常展示，不出现无效日期文案。
- [ ] 旧快照分享缺少时间戳时不回查原会话，正文正常展示且不显示时间分隔。
- [ ] 纯逻辑测试覆盖首条今天/非今天、同日/跨日、昨天/前天、今年/跨年及显式时区边界。

## Out of Scope

- 按固定分钟间隔重复显示时间。
- 增加时区选择器或修改用户时区设置。
- 修改消息排序、会话分支、删除、流式协议语义或模型上下文。
- 为消息数据库表新增时间字段；数据库消息已经具有 `createdAt`。
