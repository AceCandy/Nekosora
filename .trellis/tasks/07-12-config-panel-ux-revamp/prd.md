# 后台配置页 UX 整改：限高一屏 / 用量查询合一 / tab 重命名 / 标题统一

## Goal

统一 (dash) 段（/panel 与 /admin）后台配置页的布局与视觉：页面固定一屏、侧栏 tab 命名规整、右侧标题样式统一、用量查询合并为单一页面并按权限做数据隔离。

## Background

用户反馈四点：
1. 配置页（如"我的用量"）右侧内容过长导致整页超出视口，未限制在一屏内。
2. "我的用量"应改名"用量查询"；管理员此前可查询所有用户用量的能力似乎丢失——实际 `/admin/usage` 跨用户页仍在，但侧栏无入口，admin 只能进 `/panel/usage`（查自己）。
3. 侧栏 tab 命名零散，需统一（密钥管理 / 服务商管理 / 模型管理 / 提示词模板 / 长期记忆 / 账号管理 / 系统设置 等）。
4. 各页右侧标题样式不一致（有的有图标+描述、有的只有标题），应以知识库页（图标 + 标题 + 第二行描述）为标杆统一。

## Scope（任务地图）

父任务仅持有需求与跨子任务验收，不直接实现。拆为两个可独立规划 / 实施 / 归档的子任务：

| 子任务 | 范围 | 对应需求 |
|---|---|---|
| `07-12-shell-layout-page-header` | AppShell 限高一屏、抽 PageHeader 组件、统一非用量页标题、侧栏 tab 重命名 | 需求 1 / 3 / 4（用量页标题除外）|
| `07-12-usage-page-unify` | 合并 /panel/usage 与 /admin/usage 为单一页面、按权限数据隔离、admin 默认查自己、用量页标题统一 | 需求 2 + 用量页标题 |

执行顺序：**先 shell-layout-page-header**（产出 PageHeader 组件 + 限高 + 命名），**后 usage-page-unify**（合并时复用 PageHeader）。

## Acceptance Criteria（跨子任务）

- [ ] (dash) 所有配置页固定一屏，侧栏与品牌区固定可见，右侧内容在框内滚动。
- [ ] 侧栏 tab 命名统一（见子任务 PRD 清单），中英文同步。
- [ ] 所有配置页右侧标题样式一致：图标 + 标题 + 第二行描述（`admin/page` 主页除外）。
- [ ] 用量查询为单一入口；admin 默认查自己、可切换查全部用户、可见用户列与上游 key；普通用户隐藏用户筛选、强制隔离仅查自己。
- [ ] 普通用户构造 URL 传 `user` 参数无法越权查他人数据（服务端强制）。
- [ ] `pnpm check` + `pnpm test` 通过。

## Constraints

- 遵循 DESIGN.md「星枢天流」与「克制」原则：无彩色粗条、无 Eyebrow 眉标、静止无投影、冷调底色。
- 颜色用设计 token，不引入裸 hex。
- Server Components 默认；数据隔离必须在服务端强制，不依赖前端隐藏。
- 中英文案（zh-CN / en）同步。
