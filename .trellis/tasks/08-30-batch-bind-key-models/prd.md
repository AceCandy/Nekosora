# 批量绑定子密钥模型

## Goal

让用户在密钥管理中一次选择并绑定多个模型，减少逐个重复操作，同时保持子密钥属主隔离和模型可用性校验。

## Background

- 当前 `KeysManager` 使用单选 `Select`，客户端和 Server Action 都只提交一个 `modelId`。
- `key_model_bindings` 已按“一条记录对应一个模型”存储，并通过 `(keyId, modelId)` 唯一索引防止重复绑定，因此无需数据库迁移。
- 项目已有支持 `mode="multi"` 的 `OptionPicker`，可复用现有 Popover、多选状态与无障碍语义。

## Requirements

- 将“绑定新模型”的单选控件替换为可多选的 `OptionPicker`，允许连续勾选多个未绑定模型。
- 多选项使用方形复选指示；面板宽度与表单主控件协调，显示名称作为主信息、模型 ID 作为次信息，不重复展示同一来源徽章。
- 触发器展示待绑定数量；未选择模型时绑定按钮不可提交。
- 已绑定模型不再出现在待选列表中；切换子密钥时清空尚未提交的选择。
- 一次提交只调用一次 Server Action；Action 接收 `modelIds` 数组，去重后统一校验。
- Server Action 必须确认目标是当前用户拥有的子密钥，并确认全部模型均属于当前用户且处于启用状态；任一模型无效时不得写入任何新绑定。
- 使用单条多行插入完成批量写入，并依赖现有唯一索引幂等忽略并发产生的重复绑定。
- 保持现有单个解绑、密钥禁用、已绑定模型展示行为不变。
- 补齐中文和英文界面文案，不新增依赖或数据库迁移。

## Acceptance Criteria

- [x] 用户可以打开模型选择器，连续勾选两个或以上未绑定模型，并看到已选数量。
- [x] 多选展开态使用清晰的复选视觉、协调的面板宽度和紧凑的信息层级，不再重复展示 `BYO`。
- [x] 点击一次绑定后，所有有效选择同时出现在该子密钥的已绑定模型列表中，待选状态被清空。
- [x] 已绑定模型不会重复出现在待选项中；并发重复提交不会新增重复记录或导致整个有效批次失败。
- [x] 空选择不能提交；含空 ID、越权模型、已停用模型或不存在模型的批次整体拒绝，且不产生部分写入。
- [x] master key、其他用户的 key 和其他用户的模型仍不能被绑定。
- [x] 现有单模型解绑功能保持可用。
- [x] 定向绑定测试覆盖批量成功、去重、无效批次零写入与属主隔离；改动文件通过 lint/typecheck。

## Out of Scope

- 批量解绑、全选/反选、搜索和模型分组改版。
- 修改模型可见性规则、子密钥权限语义或数据库结构。
- 为其他页面抽象新的通用批量操作框架。

## Key Decisions

- 复用现有 `OptionPicker` 多选模式，不新建选择器组件。
- 用“统一校验后单条多行插入”保证无效批次零写入；无需额外事务封装。
- 本任务为单一页面的小范围交互增强，采用 PRD-only 轻量流程。

## Risks and Deferred Items

- 模型较多时暂不增加搜索；只有实际出现选择效率问题时再单独评估。
- UI 通过过滤隐藏已绑定模型，数据库唯一索引和冲突忽略负责并发兜底。
