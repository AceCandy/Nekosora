# 管理员重置用户密码

## Goal

在管理员用户页提供安全的用户密码重置能力，使管理员无需接触数据库即可为其他用户设置新密码，并立即阻断该用户已有登录会话。

## Background

- 用户密码由 Better Auth 管理，凭据哈希存储在 PostgreSQL `account.password`。
- 当前管理员用户页只有启停和删除操作，没有创建、设置、修改或重置密码入口。
- 当前认证配置要求密码长度为 8–128 位。

## Requirements

- 只有已通过现有 `requireAdmin` 校验的管理员可以执行重置。
- 管理员只能为其他用户重置密码，不能从该入口重置当前登录管理员自己的密码。
- 管理员选择目标用户后，必须输入并确认同一个新密码；密码长度必须为 8–128 位。
- 重置必须通过项目当前 Better Auth 版本提供的密码接口完成，不直接写入密码哈希。
- 密码重置成功后，必须撤销目标用户的现有会话。
- 管理员页必须明确展示成功、校验失败和服务端失败反馈，提交期间禁止重复提交，失败后保留输入以便重试。
- 如果密码更新成功但会话撤销失败，必须明确提示“密码已更新但会话撤销失败”，不得显示完整成功；管理员可用同一密码立即重试。
- 密码不得写入日志、错误反馈、URL 或客户端持久化状态。
- 新增文案必须同步项目现有语言包。
- 交互必须复用现有按钮、输入框与弹层/渐进式操作模式，并满足键盘操作、焦点和错误提示可访问性。

## Out of Scope

- 邮件重置链接、验证码或通知系统。
- 自动生成或展示随机密码。
- 首次登录强制修改密码。
- 普通用户自助修改/找回密码。
- 用户创建流程、seed 管理员流程或数据库迁移。

## Acceptance Criteria

- [ ] 管理员用户页为非当前用户提供可发现的“重置密码”操作，当前管理员自身不出现该操作。
- [ ] 两次输入不一致、少于 8 位或超过 128 位时不会提交，并显示明确错误。
- [ ] 合法提交调用 Better Auth 更新目标用户凭据，数据库中不出现明文密码写入逻辑。
- [ ] 更新成功后撤销目标用户已有会话，并向管理员显示成功反馈。
- [ ] 非管理员或无效目标用户无法通过服务端 Action 重置密码。
- [ ] 密码更新或会话撤销失败时不显示完整成功；部分失败有准确提示，表单可再次提交。
- [ ] 服务端鉴权、输入校验、调用顺序及失败分支有单测；前端表单结构、双语文案和真实交互完成对应验证。

## Technical Notes

- 项目锁定 Better Auth `1.6.23`；该版本原生提供 `auth.api.setUserPassword` 和 `auth.api.revokeUserSessions`，前者不会自动撤销会话。
- 现有用户页通过 Server Component 渲染列表，并以同目录 Client Component 承载行级操作；本功能沿用该边界。
