# 聊天体验打磨

## Goal

修复/优化聊天工作台四处体验问题：空闲态多余网络请求、AI 流式回复时历史消息操作栏消失、「回到最新」按钮常驻显示、流式生成下方缺少留白。整体遵循「星枢天流」克制设计。

## Requirements

1. **空闲态不发多余请求**：聊天工作台在用户无任何操作、且当前未处于流式回复时，不得向后端发送周期性或重复的网络请求。流式回复结束后，对应的流式通道（SSE / fetch stream 等）必须正确关闭，不得残留重连。

2. **流式时保留历史消息复制按钮**：AI 正在流式回复期间，历史已完成消息的操作栏不得整体隐藏，至少保留「复制」按钮可见且可用。仅当前正在生成的那条消息可隐藏非必要操作。

3. **回到最新按钮按需展示**：「回到最新」按钮仅在用户向上滚动、未停留在最新消息底部时显示；当已停留在最新一轮对话（滚动到底）时隐藏。

4. **流式生成下方留白**：在已有会话中发起新一轮对话、AI 流式生成时，生成内容下方预留约 2/3 屏空白，使生成内容停在视口上部、下方留白跟随（参考 Claude / GPT）；生成结束后缓冲收回、内容恢复正常贴底。

## Constraints

- 遵循「星枢天流」设计主线：无彩色粗条、静止无投影、冷调中性；不引入暖色 / 奶油色。
- Surgical：只改与上述四点直接相关的组件与逻辑，不重构无关代码、不顺手优化。
- 不破坏既有输出样式（rs-xxx）、结构化块渲染，以及正常流式回复与增量渲染。
- #1 的具体根因与修复点见 design.md（依赖代码调查结论）。

## Acceptance Criteria

- [ ] 空闲态（打开聊天页、不发送、不流式）下，浏览器网络面板无周期性 / 重复多余请求；流式回复结束后通道关闭、无重连风暴。
- [ ] AI 流式回复中，历史已完成消息的「复制」按钮可见可用。
- [ ] 滚动至最新 / 底部时「回到最新」按钮隐藏；上滑查看历史时显示。
- [ ] 已有会话发新消息、AI 流式生成时，生成内容下方留约 2/3 屏空白；生成结束缓冲收回、内容贴底。
- [ ] 未引入回归：输出样式、结构化块、流式增量渲染、明暗模式均正常。
- [ ] `pnpm lint` 通过。
