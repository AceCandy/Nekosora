# 服务商模型相似匹配与路由复用

## Goal

从服务商的上游模型列表点击模型时，优先复用已有模型并补充路由；完全匹配失败时展示相似模型候选，让用户选择复用已有模型或新建模型，减少重复模型，同时避免重复路由写入。

## Background

- `ProvidersManager.tsx` 当前点击上游模型后跳转到模型页，并携带 `name`、`providerId`、`upstreamModelName` 打开新建模型弹窗。
- `createModel` / `createMyModel` 当前可在同一事务中创建模型和初始路由，但同名模型只会抛出 `MODEL_ALREADY_EXISTS`，不会复用已有模型或补路由。
- `routes` 当前没有 `(modelId, providerId, upstreamModelName)` 唯一索引，因此新入口必须在服务端再次检查，不能只依赖前端状态判断。
- 现有 `findCatalogMatch` 面向模型模板，只支持 canonical ID / alias 的大小写归一精确匹配，不提供已有模型的相似候选排序。

## Requirements

- R1. 用户点击服务商 `providerId` 下的上游模型 `upstreamModelName` 后，系统必须先在当前用户可管理的模型范围内按模型对外 ID 做完全匹配。
- R2. 若完全匹配模型已存在，且该模型已有相同 `providerId + upstreamModelName` 的路由，界面显示“已存在”，不得写入模型或路由。
- R3. 若完全匹配模型已存在，但相同路由不存在，系统直接为该模型创建路由，不创建模型。
- R4. 若完全匹配失败，系统展示按相关度排序的相似模型候选，并始终提供“新建模型”选项。
- R5. 用户选择相似候选后，若候选已有相同 `providerId + upstreamModelName` 的路由，界面显示“已存在”，不得写入；否则仅为候选模型创建路由。
- R6. 用户选择“新建模型”后，沿用现有模型表单，预填上游模型 ID，并在提交成功时原子创建模型和路由。
- R7. 完全匹配、相似候选选择和最终写入均须遵守 admin / panel 现有可见性、属主和服务商管理权限。
- R8. 服务端写入口必须执行重复路由检查，防止过期页面或重复点击造成重复数据。
- R9. admin 与 panel 两套入口行为保持一致，界面文案同时维护中英文。
- R10. 完全匹配使用去除首尾空格后的严格字符串相等；大小写、命名空间或分隔符差异进入相似候选流程。
- R11. 相似候选按以下置信顺序生成：同目录模板、归一 ID 相同、去明确发布日期或 `latest` 后相同、完整 ID 包含、保守词元相似。
- R12. 相似匹配只忽略大小写、最后一段厂商命名空间、空格/下划线/重复分隔符、尾部 `YYYYMMDD`、`YYYY-MM-DD` 或 `latest`；不得忽略型号、尺寸及 `mini`、`nano`、`pro`、`flash`、`reasoning`、`coder`、`vision`、`preview` 等能力/档位词。
- R13. 保守词元相似至少共享两个词元，并同时满足词元重合与字符顺序阈值；`8b`、`32b`、`70b` 等参数规模冲突时不得成为候选。
- R14. 候选按置信度降序，分数相同保持已有模型顺序，最多展示 5 个；任何候选都不得自动选中或自动写入。
- R15. 候选项展示对外模型 ID、模型模板与路由状态，底部始终提供使用当前上游 ID 新建模型的入口。

## Out of Scope

- 不修改模型目录 `model_catalog` 的匹配、能力或模板数据。
- 不自动合并、改名或删除已有模型。
- 不处理服务商列表之外的模型/路由创建入口。

## Acceptance Criteria

- [x] 完全匹配且同一路由存在时显示“已存在”，模型数和路由数均不变。
- [x] 完全匹配但同一路由不存在时只新增一条路由。
- [x] 完全匹配失败时展示相似候选与“新建模型”，不直接写入数据。
- [x] 选择已有候选且同一路由存在时显示“已存在”，不写数据。
- [x] 选择已有候选且同一路由不存在时只新增一条路由。
- [x] 选择“新建模型”时创建一个模型和一条对应路由。
- [x] 无相似候选时仍可进入新建模型流程。
- [x] 服务端拒绝越权绑定，并对重复请求保持幂等。
- [x] admin 与 panel 的上述场景都有自动化测试覆盖。
- [x] `zai/glm-5.2` / `glm_5.2` / 带明确发布日期的同系列 ID 能进入合理候选。
- [x] `claude-sonnet-4` 与 `claude-opus-4`、`gpt-4o` 与 `gpt-4.1`、`llama-3.1-8b` 与 `llama-3.1-70b` 不会因宽松字符相似而成为候选。

## Notes

- 路由是否相同按 `modelId + providerId + upstreamModelName` 判断；同一模型在同一服务商下指向不同上游 ID，仍是不同路由。
- 本次不增加 `routes` 唯一索引；服务端写入口在插入前复查重复路由，解决既有入口的重复点击行为。存量数据清理与并发级唯一约束另行评估。
