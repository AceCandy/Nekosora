# MAGI 项目进化第 6 轮

## Goal

修复消息编辑物理删除后代导致新分享快照丢失的问题，使“编辑不改变旧分享正文”与“显式软删除可撤回公开内容”同时成立。

## Background

- `editMessage` 原地修改 user 消息，并物理删除其全部后代（`src/features/chat/actions/branch.ts:327`）。
- `softDeleteMessage` 不物理删除，而是给目标及后代设置 `deletedAt`（`src/features/chat/actions/branch.ts:477`）。
- 新分享已保存有序正文快照，但 `getShare` 当前只查询未软删除且仍存在的消息，再用该集合过滤快照（`src/features/chat/actions/share.ts:77`）。
- 因此编辑已分享 user 消息后，原 assistant 后代从数据库消失，旧分享也错误丢失其冻结正文。
- 项目内消息物理删除目前仅存在于编辑主线流程；删除会话时分享记录通过外键级联一并删除。

## Requirements

- 对带正文快照的新分享，当前消息记录物理缺失时必须继续返回创建时快照。
- 对带正文快照的新分享，当前消息记录存在且 `deletedAt` 非空时必须隐藏对应快照。
- 对历史 `message_snapshots_json IS NULL` 分享，继续只返回当前存在且未软删除的实时正文。
- 所有路径继续按分享保存顺序返回消息，并限制消息状态查询到分享所属会话和已保存 ID 集合。
- 不修改编辑、续写、软删除、分享撤销或数据库 schema。

## Acceptance Criteria

- [x] 新分享中的 assistant 消息被编辑流程物理删除后，公开链接仍返回创建时正文和顺序。
- [x] 新分享中的消息被显式软删除后，公开链接隐藏对应快照；全部软删除时仍保留现有空消息元数据契约。
- [x] 新分享中仍存在但正文被编辑/续写的消息继续返回冻结正文。
- [x] 历史 null 快照分享不返回物理缺失或软删除消息，并继续动态读取现存正文。
- [x] 消息状态查询同时包含 `conversationId` 和已保存 publicId 集合，不扩大读取范围。
- [x] 撤销、属主校验和分享创建全集校验不回归。
- [x] lint、typecheck、全量测试和生产构建通过。

## Out Of Scope

- 改变编辑主线物理删除后代的行为。
- 为历史分享回填正文快照。
- 改变全部消息软删除后仍返回分享元数据的既有契约。
- 处理分享页面缓存策略、剪贴板错误提示或其他独立审计项。
