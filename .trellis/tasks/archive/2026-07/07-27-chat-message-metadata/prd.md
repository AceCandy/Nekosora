# 聊天回复运行元数据

## Goal

让登录用户在不增加聊天正文常驻噪声的前提下，查看每条 AI 回复所用的平台模型、实际 Token 用量、整轮耗时和精确完成时间；同时从普通聊天中移除含义不清的上下文追踪面板。

## Background

- 当前 AI 回复底部没有模型、实际用量、整轮耗时或时间戳；`ChatMessage` 只包含正文、思考、上下文追踪等字段（`src/features/chat/model/types.ts:13`）。
- `runs` 已按本轮生成保存 `platformModelName` 和 `tokenUsage`，assistant 消息通过 `messages.runId` 关联该 run（`src/db/schema/pg.ts:372`、`src/db/schema/pg.ts:419`）。
- `/api/chat` 已收到最终实际 usage，但当前前端 SSE 契约未处理 `finish`，因此实时消息拿不到实际用量（`src/app/api/chat/route.ts:446`、`src/features/chat/model/sse.ts:20`）。
- 当前“路由链路追踪”展示的是压缩前后消息数、上下文块和 Token 估算，不包含供应商路由、故障转移或实际用量（`src/features/chat/components/ChatMessageItem.tsx:810`、`src/lib/trace.ts:15`）。
- 公开分享使用只读正文投影，当前不携带登录态消息操作或运行元数据（`src/features/chat/components/ReadonlyChatMessage.tsx:15`）。

## Requirements

### R1. 展示内容与语义

- 仅在 assistant 回复完成后展示该回复可用的运行元数据：
  - 用户选择的平台模型名；
  - 输入 Token；
  - 输出 Token；
  - 缓存读取 Token；
  - 思考 Token；
  - 整轮耗时；
  - 回复完成时间，精确到秒。
- “整轮耗时”定义为 `/api/chat` 收到本轮请求至 assistant 必要消息持久化完成的墙钟耗时，包含上下文准备、路由/故障转移、工具多轮、模型生成和必要消息收尾；不包含异步记忆任务或后续 best-effort run 审计等待。
- Token 子项只展示上游实际返回并成功归一化的值。缺失字段不伪造为 `0`，也不把缓存或思考 Token 额外累加成新的“总 Token”。
- 普通聊天只展示平台模型，不展示供应商、上游 Key、真实上游模型或故障转移细节。

### R2. 低干扰与可访问交互

- 桌面精细指针环境下，元数据默认不抢占视觉注意力；hover 当前 assistant 回复时淡入，键盘焦点进入该回复操作区时同样可见。
- hover/focus 显隐不得改变消息高度、推挤相邻消息或导致操作按钮跳位。
- 触屏/粗指针环境不得依赖 hover；提供带可访问名称、至少 44×44px 的信息按钮，点击后在原消息内展开/收起同一组元数据。
- 长模型名和窄屏必须安全截断或换行，320px 起不得产生页面级横向滚动。
- 使用现有语义字号、品牌中性色和 Lucide 图标；每个非显然图标必须有 tooltip 或等价可访问名称。

### R3. 实时与历史一致

- 新生成回复在流结束后无需刷新即可出现元数据。
- 刷新、重新进入会话或切换 assistant 版本后，显示与该消息 `runId` 对应的同一组元数据。
- 普通发送、重新生成、编辑重发和续写都必须绑定各自本轮 run；续写后显示最新续写 run 的耗时和完成时间。
- 历史 run 缺少新增字段时按字段降级：保留已有模型/Token，隐藏缺失的耗时或完成时间，不显示错误占位值。

### R4. 普通聊天移除上下文追踪

- 普通聊天不再渲染现有“路由链路追踪”折叠面板。
- `/api/chat` 不再向普通聊天客户端发送 trace SSE；客户端消息类型、SSE handler、store 和历史消息映射不再携带 `ProcessTrace`。
- 服务端继续构建 trace 并写入现有 `messages.processTrace`，保留未来开发者诊断的可回滚基础。
- 不删除 `messages.process_trace` 列，不改变 `ProcessTrace` 数据结构、构造逻辑或服务端持久化内容。
- 删除只被该普通聊天面板使用的中英文 i18n 文案，避免孤立资源。

### R5. 隐私与范围边界

- 元数据仅在已鉴权聊天会话中展示；历史 run 查询必须限定当前用户已授权的 conversation。
- 公开分享页、分享快照和只读消息组件不暴露模型、Token、耗时或时间戳。
- 不暴露明文或脱敏后的上游 Key。

### R6. 兼容与数据迁移

- 新增数据库字段必须允许 `NULL`，不要求对历史记录做推测性回填。
- PostgreSQL 迁移必须追加新文件，并同步 Drizzle journal 和 snapshot；不得修改已发布迁移。
- 现有消息、run 活动租约、工具调用、用量日志和路由行为保持兼容。

## Acceptance Criteria

- [ ] AC1（R1、R2）：完成一条 AI 回复后，桌面 hover 或操作区键盘聚焦会显示平台模型、所有可用实际 Token 子项、整轮耗时和精确到秒的完成时间；移出/失焦后淡出且消息布局不移动。
- [ ] AC2（R2）：在粗指针 320px 与 390px 视口中，可通过 44×44px 信息按钮展开/收起元数据，无横向溢出、文字遮挡或只能 hover 才能访问的内容。
- [ ] AC3（R3）：普通发送、重新生成、编辑重发和续写均在当前流结束后即时绑定正确元数据；刷新会话及切换回复版本后数据仍与对应 run 一致。
- [ ] AC4（R1、R3）：当上游不返回缓存或思考 Token 时，对应项不出现；真实值为 `0` 时可以显示 `0`，未知值不得显示为 `0`。
- [ ] AC5（R3、R6）：旧 run 的新增字段为 `NULL` 时页面正常渲染，已有模型/Token 仍可显示，缺失项被隐藏。
- [ ] AC6（R4）：普通聊天不再出现上下文/路由追踪面板，网络流和客户端消息状态不再包含 trace；服务端 assistant 持久化仍保留 `processTrace`，既有数据库列不删除。
- [ ] AC7（R5）：公开分享页和分享快照不包含运行元数据；历史元数据查询不能跨 conversation 或跨用户读取 run。
- [ ] AC8（R6）：新增迁移、journal、snapshot 与 schema 一致，既有数据库可向前迁移，既有 run 生命周期测试保持通过。
- [ ] AC9：相关 lint、类型检查、单元测试通过；桌面/移动、亮色/暗色及键盘焦点完成浏览器核验。

## Out of Scope

- 在聊天消息中展示真实供应商、上游模型、路由、Key、重试/故障转移时间线。
- 新增管理员“请求路由详情”界面。
- 新增或改造开发者专用的“上下文诊断”界面。
- 展示 TTFT、生成速度、费用、总 Token 或 cache write Token。
- 为 user 消息增加时间戳或运行统计。
- 对历史 run 推测性回填整轮耗时或完成时间。
- 删除 `messages.process_trace` 列、停止服务端 trace 构建/持久化，或修改 `ProcessTrace` 数据结构。
- 修改模型目录、路由算法或计费聚合。

## Risks And Deferred Items

- 不同供应商对缓存和思考 Token 的上报能力不同；MVP 只能准确展示归一化层实际拿到的字段。
- run 终结属于现有 best-effort 审计写入；极端数据库故障时，实时元数据可能已显示而刷新后缺失。该异常沿用现有 run 审计降级契约，不在本任务中升级为主流程强一致写入。
- 服务端继续保存当前粒度的 `ProcessTrace`，其长期存储收益和增长成本留待开发者诊断功能立项时重新评估。
- 实现涉及当前分享弹窗任务也可能修改的 i18n/聊天组件文件；进入实现前必须重新读取工作树并保留对方改动。
