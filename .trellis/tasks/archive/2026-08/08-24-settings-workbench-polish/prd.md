# 系统设置工作台顶级化

## Goal

在不改动既有真实服务端设置控制契约的前提下，将 `/admin/settings` 从功能完整但常规的设置页升级为能直接体现活动变更集、原子发布和指定发布反向撤销优势的生产配置工作台，使管理员能快速定位配置，并在发布前准确理解变更内容与影响。

## Background

- 上一任务已经完成唯一活动草稿、单调 revision、整批原子应用、发布历史、指定发布反向撤销和治理小时聚合；本任务只改进 Web 设置体验，不重做这些服务端能力。
- 当前顶部搜索/分类条使用 `sticky top-0`，底部变更控制使用 `sticky bottom-4`，在窄屏和长表单中会同时占据视口。
- 当前四个顶层分类为“模型与任务 / 输出体验 / 流量治理 / 网关协议”；“输出体验”内部同时包含改变模型行为的输出模式和改变渲染外观的输出样式，但缺少明确二级目录。
- 当前活动草稿与发布历史只显示变更数量、resource key 和创建/删除/更新，未把已经持久化的 `before/after` 转成面向管理员的发布影响摘要。
- 设计评审基线为 28/40；静态 AI 反模式扫描 0 命中。

## Requirements

### R1. 单一工作台控制面

- 删除顶部与底部双 sticky 竞争；桌面宽屏使用一个活动变更集控制面，窄屏不允许两个完整吸附工具条同时存在。
- 无草稿时仍清楚展示当前 revision 与发布历史入口；有草稿时突出变更数量、持久化状态、放弃和审查发布入口。
- 保留现有服务端 action、乐观锁、应用、放弃和反向撤销语义，不新增绕过变更集的写路径。

### R2. 清晰的信息架构

- 保留四个顶层分类与全部旧 query alias，不新增第五个全局 Tab。
- “输出体验”内部明确区分“行为模式”和“视觉渲染”，提供可见的二级目录、解释和锚点定位。
- 设置搜索结果显示所属路径，并支持键盘选择、Escape 关闭及正确的组合框可访问语义。

### R3. 发布前影响摘要

- 审查发布必须成为独立确认步骤，不能从资源键列表直接提交。
- 摘要按设置领域归组，显示创建/删除/更新、受影响资源、变更字段和可用的 before → after。
- 对删除、治理策略、自定义渲染/CSS 等高影响变更给出基于确定事实的重点确认提示；不得伪造运行风险预测。
- 长文本和结构化值默认摘要展示，允许按需展开，避免发布审核被原始 CSS、Prompt 或 JSON 淹没。
- 发布历史复用同一套人类可读差异呈现，并继续支持无活动草稿时创建反向撤销草稿。

### R4. 已确认规范修复

- 信息性文字不使用低于 `DESIGN.md` 要求的 `text-neutral-400`；装饰图标可保留。
- 状态色使用 semantic token；历史时间显式使用当前应用 locale。
- 修复未定义的 `text-ui-subtitle`。
- 新增或修改的输入、弹层和按钮满足现有 focus-visible、44px 触屏目标、i18n 和亮色主题约束。

## Acceptance Criteria

- [ ] 320/390/768/1280px 下没有顶部与底部双 sticky 竞争、不可达操作或横向裁切。
- [ ] 四个顶层分类、旧 query alias 和全部现有设置能力保持可达。
- [ ] 输出体验能在进入页面后立即识别“行为模式”和“视觉渲染”，并可直接跳到对应工作区。
- [ ] 设置搜索结果显示分类路径，可用方向键与 Enter 选择，Escape 关闭，焦点和 ARIA 状态正确。
- [ ] 有草稿时，管理员必须先看到按领域归组的影响摘要，再触发原有原子 apply action。
- [ ] 影响摘要对创建、删除、更新和字段变化使用人类可读标签；长文本默认折叠，不只展示 resource key。
- [ ] 发布历史使用同一差异呈现；反向撤销仍只在无活动草稿时可用，服务端冲突反馈不丢失。
- [ ] revision、草稿持久化、放弃、发布、历史和回滚的服务端契约与上一任务保持兼容。
- [ ] 本轮涉及的设计 token、本地化和无效字号问题已修复，定向静态扫描无新增命中。
- [ ] Web 设置页定向测试、lint、typecheck 和 `git diff --check` 通过；浏览器受环境阻断时如实报告未验证。

## Validation Constraint

- 当前本地 Web 会因 PostgreSQL 迁移账本 hash 不一致而无法启动；实施完成后必须重新尝试，若仍阻断则保留原始错误并明确标记浏览器验收未完成。

## Out of Scope

- 修改数据库迁移、settings-control 事务、运行时缓存代际或治理聚合采集。
- 新增多管理员审批、命名草稿、评论、强制回滚或跨管理员协作。
- 为治理阈值生成没有可靠数据依据的推荐值或未来风险保证。
- 改造 Chat 页、全局后台侧栏或设置页之外的存量 `text-neutral-400`。

## Key Decisions

- 复用现有 `SettingsChange.before/after` 和 Server Actions，不新增 API、依赖或第二套差异模型。
- 顶层继续保持四域；通过域内二级目录解决输出行为与视觉混合，而不是增加全局导航复杂度。
- 影响提示只陈述确定事实；风险未知时不输出伪精确等级。
