# 拒绝搜索词推断年份

## Goal

无工具模型走应用侧预搜索时，阻止搜索词提取模型擅自加入用户或对话上下文未出现的年份，避免把“最新”错误改写为过时年份搜索。

## Background

- 无工具模型由 `prefetchWebSearch()` 调用 `rewriteSearchQuery()`，最终只构造 `{ query }`，不传 freshness 或日期范围（`completion-coordinator.ts:401-442`）。
- 搜索词提取结果当前只清理 Markdown、引号和拒答文本，不校验新增年份（`query-rewrite.ts:70-79`）。
- 改写失败或返回 `null` 时，调用方已自动回退到用户原问题，无需新增回退机制（`completion-coordinator.ts:402,416-424`）。
- GPT/OpenAI Hosted Search 没有项目可映射的原生 freshness 参数；本任务不伪造上游能力。

## Requirements

1. 搜索词改写结果出现 `19xx` 或 `20xx` 四位年份时，只有该年份已出现在当前用户问题或提供给改写器的对话上下文中才允许保留。
2. 改写结果包含任何无来源年份时返回 `null`，复用现有用户原问题回退；不尝试局部删除或修补模型输出。
3. 搜索词提示保留调用当下日期时间用于理解相对表达，但不再要求把“最新/最近”转换成一周或一月，也不得将相对时间改写为具体年份。
4. 不修改应用侧 `{ query }` 调用形状，不给不支持的 GPT Hosted Search 伪造 freshness 或日期参数。

## Acceptance Criteria

- [x] 用户和上下文都未包含年份，模型输出 `DeepSeek 模型最新价格 2025` 时，`rewriteSearchQuery()` 返回 `null`。
- [x] 用户问题明确包含 `2025`，模型输出包含 `2025` 时正常返回改写结果。
- [x] 当前问题未写年份、但传入的对话上下文明确包含 `2025` 时允许保留。
- [x] 搜索词提示仍包含动态当前日期时间，并明确保持相对时间原意、禁止推断年份。
- [x] 现有拒答、Markdown 清理和无改写模型回退行为保持不变。
- [x] `query-rewrite` 定向测试、Core 类型检查和 `git diff --check` 通过。

## Out of Scope

- 不修改工具模型的 `web_search` 参数校验。
- 不新增 freshness、日期范围或搜索供应商能力。
- 不解析、删除或重组含错误年份的模型输出。
- 不覆盖 1900—2099 以外的数字，也不把普通四位数字当作年份处理。
- 不修改搜索结果排序、缓存或界面展示。

## Risk

- 合法但由模型自行补充、且未在用户问题或上下文出现的年份会触发整条改写回退；这是保守且可恢复的预期行为。
