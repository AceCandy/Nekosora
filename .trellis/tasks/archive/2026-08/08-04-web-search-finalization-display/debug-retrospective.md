# 缺陷复盘：搜索完成后生成未正常结束与逐调用信息缺失

## 1. 根因分类

- **分类**：B - 跨层契约不完整（主因）；D - 测试覆盖缺口（促成因素）。
- **具体原因**：Agent loop 把工具轮次上限当成可直接结束的边界，但 coordinator 只接受真实 `finish` 为成功；后续又把“工具后的模型轮收到 finish”误当成有正文的成功，没有验证该轮是否产生非空 `text-delta`。前端还把逐调用来源压缩成消息级聚合后端，丢失了 `toolCallId` 关联。

## 2. 之前设计为何未阻止问题

1. Agent loop 测试曾明确固化“轮次耗尽时不发 finish”，只验证局部循环，没有验证 coordinator 会把自然 EOF 转成“生成未正常完成”。
2. 组件测试曾明确固化“仅第一条搜索显示聚合后端”，没有覆盖同名工具多次调用且后端/状态不同的场景。
3. 历史恢复只验证消息级引用与后端，未验证 process trace、tool_calls 与 UI 之间按 `toolCallId` 的逐调用契约。
4. 首次补丁只覆盖“轮数耗尽后的强制总结”，没有用截图对应的“一次工具调用后正常 finish 但正文为空”路径复现，导致修复分支选错。

## 3. 预防机制

| 优先级 | 机制 | 具体动作 | 状态 |
| --- | --- | --- | --- |
| P0 | 架构 | 工具轮耗尽后只允许一次 `tools: undefined` 的收敛请求 | DONE |
| P0 | 测试 | 覆盖唯一 finish、聚合 usage、总结失败/取消与不重复执行工具 | DONE |
| P0 | 测试 | 覆盖工具后正常轮只有 finish、没有正文时的一次无工具重试 | DONE |
| P0 | 跨层契约 | SSE、store、历史投影与组件统一按 `toolCallId` 关联 | DONE |
| P0 | 数据安全 | 历史失败说明只投影固定安全文案，未知文本不展示 | DONE |
| P1 | 规范 | 更新 Chat 终态和 Web Search 逐调用投影规范 | DONE |

## 4. 系统性扩展

- **类似问题**：其他允许同名工具重复调用的 UI 也不能按工具名或数组位置合并状态。
- **设计改进**：消息级聚合字段只用于兼容展示；任何逐调用状态必须保留稳定调用 ID。
- **流程改进**：流式终态改动需同时验证生成器、coordinator、SSE 与客户端，而不是只测单层自然结束。
- **纠正规则**：截图显示的调用次数和终态必须先映射到真实循环分支，再写回归测试；不能用相邻但不同的失败分支代替复现。
