# 重新设计完整设置中心

## Goal

重做由共享左侧导航承载的完整设置中心，而不是只优化 `/admin/settings`。用户应能在一个一致、清晰的设置外壳中管理个人配置与全局配置，从左侧导航或搜索直接进入目标任务；各页面保留现有业务能力、权限和 URL，同时统一信息层级、内容密度、反馈语言与响应式行为。

## Background

- 产品意义上的设置中心跨越 `/panel/*` 与 `/admin/*`，不能用单个路由目录界定范围。
- 当前左侧导航已经是设置中心的主导航，并按“我的配置”和“全局管理”分组；`/admin/settings` 只是全局管理中的一个入口。
- 当前 `/admin/settings` 又在内容区重复放置搜索和四个大 Tab，形成“设置中心主导航里再套一套设置导航”的层级冲突。
- 系统设置的输出页连续渲染两个完整管理器，治理页同时承载策略与历史，仍有长画布问题。
- `SettingsChangeControl` 常态展示内部 revision（如 `r0`），局部表单却只显示“已保存”，没有准确表达“进入草稿、尚未发布”。
- 各页面已经复用 `PageHeader`，但页面容器、满高工作区、筛选、表格、管理器与响应式策略并不一致。

## Confirmed Scope

### 我的配置（所有登录用户）

- 密钥管理：`/panel/keys`
- 服务商管理：`/panel/providers`
- 模型管理：`/panel/models`
- 联网搜索：`/panel/web-search`
- 指令卡：`/panel/cards`
- 长期记忆：`/panel/memory`
- 用量查询：`/panel/usage`

### 全局管理（仅管理员）

- 账号管理：`/admin/users`
- 运维监控：`/admin/operations`
- 系统设置：`/admin/settings`

## Requirements

### R1. 设置中心外壳与主导航

- 共享左侧导航是整个设置中心唯一主导航；不在系统设置内容区复制一套全局搜索或主导航。
- 搜索放在左侧导航顶部，覆盖当前用户有权访问的设置范围。
- 保留“我的配置 / 全局管理”的权限分组；普通用户不得看到或通过搜索发现管理员入口。
- 保留现有 `/panel/*`、`/admin/*` URL、管理员守卫、个人数据隔离与侧栏收起/移动抽屉能力。
- “返回聊天”、侧栏收起、快捷键与当前页高亮在重设计后继续可用。

### R2. 全局一致性

- 十个入口使用一致的页面标题、说明、主操作、搜索/筛选和内容起始位置。
- 根据任务类型使用少量明确的页面模板：配置表单、资源管理、数据查询/监控；不强行把所有页面变成相同卡片布局。
- 统一创建、编辑、删除、测试、保存、加载、成功、失败与空状态的交互语言和视觉层级。
- 可逆的启用状态统一在状态列直接切换，操作列不再重复展示启用/停用按钮；没有其他行级动作时移除空余操作列。
- 高密度资源管理页面可保留满高工作区；表单页和阅读页保持可读宽度，不用一套固定容器抹平差异。

### R3. 页面级任务边界

- 密钥、服务商、模型、联网搜索、指令卡、长期记忆、用量、账号和运维各自保留现有业务职责，不借重设计扩展功能。
- 指令卡只属于创建者本人；不再区分内置、共享或私有范围，其他用户不能查看、选择、编辑或删除。
- 资源管理页应让列表、当前选择、编辑/预览和主要动作关系明确，避免长列表与编辑器互相挤压。
- 数据查询和运维页面应把筛选、摘要与明细建立清楚的上下层级，在窄屏避免整个页面意外横向滚动。
- 个人配置与全局管理在标题、说明和权限提示上可辨认，但不额外制造装饰性标签。

### R4. 系统设置内部重组

- 移除系统设置内容区的全局搜索；其搜索能力并入设置中心左侧搜索。
- 系统设置内部保留必要的二级结构，但一次只显示一个具体工作区。
- 模型配置至少区分 Embedding 与后台任务模型。
- 输出体验拆分为行为模式与视觉渲染，两个完整管理器不再出现在同一长页。
- 输出样式列表不常驻渲染预览；用户点击每条样式的小眼睛后，在弹窗中按需查看真实 Markdown 样例。
- 流量治理拆分为策略配置与运行历史，编辑任务与分析任务不再混排。
- 网关协议保持独立工作区。
- 旧 `tab` 值、旧别名和现有字段锚点继续映射到等价新位置。

### R5. 草稿与发布

- 普通设置界面不展示 `r0`、`r42` 等内部 revision；底层 revision、乐观并发、缓存代际、发布历史和回滚机制保持不变。
- 无活动草稿时不常驻发布控制卡；有草稿时明确显示待发布变更数和“审核并发布”。
- 系统设置的局部保存反馈统一表达为“已保存到待发布草稿”，不能让用户误以为已经生效。
- 发布审查保留人类可读差异；revision 只在历史、冲突诊断等确有价值的上下文中显示。
- 窄屏编辑长内容时仍能访问待发布状态与发布动作。

### R6. 视觉、响应式与无障碍

- 遵循“星枢天流”product register：冷调纯白、莫兰迪中性层级、克制使用天空蓝、静止无投影、固定语义字号。
- 不新增暗色模式、装饰性动效、毛玻璃、彩色侧边粗条、无意义卡片嵌套或新的 UI 依赖。
- 320、390、768、1280px 下，主导航、页面内容、表单、管理器、表格和发布入口均可理解、可操作。
- 保留或补全触控目标、键盘导航、焦点样式、读屏标签、状态公告和 `prefers-reduced-motion`。
- 中英文文案同步，长中文/英文标签不溢出容器。

## Acceptance Criteria

- [ ] 设置中心左侧导航完整承载 7 个个人入口和管理员可见的 3 个全局入口，系统设置不再重复全局搜索与主导航。
- [ ] 左侧搜索覆盖页面入口和主要设置项，只返回当前用户有权访问的目标，并能进入正确页面或系统设置子工作区。
- [ ] 十个入口的页头、主要操作、反馈与内容起始位置形成一致系统，同时保留表单、资源管理、数据页面的必要差异。
- [x] 服务商、模型、账号、输出模式与输出样式使用一致的状态开关，模型路由保留有效状态与本地开关的独立表达。
- [ ] 输出模式/视觉渲染、治理策略/运行历史不再同时渲染于同一长页面。
- [ ] 输出样式主列表无常驻预览，点击行内预览按钮后才展示对应样式效果。
- [ ] 常规状态不显示内部 revision；底层发布、冲突检测、历史、回滚和缓存行为不变。
- [ ] 系统设置局部保存明确告知进入待发布草稿，有草稿时可持续访问审核、发布与放弃操作。
- [ ] 所有现有主路由、系统设置旧 tab/alias/anchor 和权限边界保持兼容。
- [ ] 指令卡不再显示或接收可见范围，列表、聊天注入与写操作均按当前用户隔离。
- [ ] 定向组件测试、相关既有测试、lint、typecheck、设计检测与 `git diff --check` 通过。
- [ ] 浏览器验证覆盖普通用户与管理员视角、320/390/768/1280px、键盘搜索、页面切换、资源管理、草稿审核与历史；环境阻断时保留原始证据并明确未验证项。

## Out of Scope

- 除移除指令卡 scope 并收紧其用户归属外，修改其他个人/全局设置的数据模型、数据库结构、权限规则或现有业务语义。
- 新增批量配置、导入导出、多管理员审批或全新管理能力。
- 重做聊天主界面、聊天侧输出模式/样式选择器或其他非设置页面。
- 为统一外观而重写已经可用的 Manager、Server Action 或后端服务。

## Key Decisions

- 左侧搜索同时覆盖页面入口和主要设置项，可直接定位“Embedding”“RPM”“User-Agent”等具体任务。
- 搜索结果必须按当前用户权限过滤；普通用户不能看到或发现管理员设置。
- 搜索元数据保持轻量，并与现有页面 URL、系统设置 tab/alias/anchor 兼容关系同步维护。
- 指令卡是用户个人配置，不提供共享或系统内置范围；旧有属主卡保留，无属主卡随迁移移除。
