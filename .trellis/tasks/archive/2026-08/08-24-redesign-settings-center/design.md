# 完整设置中心重设计方案

## 1. 设计边界

本次重设计以共享 `(dash)` 设置外壳为产品边界，覆盖 7 个 `/panel/*` 页面和 3 个 `/admin/*` 页面。现有路由、服务端数据获取、Manager、Server Action、权限与数据作用域继续作为事实源；改动集中在导航搜索、页面骨架、系统设置内部信息架构和草稿发布表达。

不新增设置首页、不迁移路由、不引入新的客户端状态库或搜索依赖。

## 2. 当前结构与根因

- `DashLayout` 已根据 pathname 执行 `requireSession` / `requireAdmin`，并把权限过滤后的 `NavGroup[]` 传给同一个 `AppShell`。
- `AppShell → DashSidebar → SidebarNav` 已统一 `/panel` 与 `/admin` 的桌面收起、移动抽屉、返回聊天和用户菜单。
- `nav-config.ts` 是十个主入口及权限分组的唯一导航事实源，但当前 `NavItem` 只有 href、labelKey、icon，无法承载页面内搜索目标。
- `/admin/settings` 在共享主导航之内又实现一套本地搜索和四个顶层 Tab；搜索只认识 8 个系统设置锚点，位置和产品范围都不正确。
- 系统设置页用 20rem 右栏常驻发布控制；无草稿时仍展示 revision，输出与治理则把多个完整任务连续堆叠。

根因不是缺少更多视觉组件，而是导航元数据、页面层级与发布状态没有对齐真实用户任务。

## 4. 导航搜索

### 4.1 元数据

在现有 `NavItem` 上增加可序列化的轻量搜索信息：

```ts
interface NavSearchTarget {
  href: string;
  labelKey: string;
  keywords: string;
}

interface NavItem {
  href: string;
  labelKey: string;
  icon: NavIcon;
  keywords?: string;
  targets?: NavSearchTarget[];
}
```

- 主项关键词覆盖页面常用叫法；targets 只收录有稳定 URL/锚点的主要设置任务。
- 系统设置复用现有字段锚点并指向新的 `tab/view` URL。
- 中英文关键词放在短字符串中，显示文案仍来自 `next-intl`。
- 不建立第二份权限表。`DashLayout` 先按角色生成 groups，搜索只处理收到的 groups，因此普通用户无法发现管理员结果。

### 4.2 交互

- 搜索输入位于展开侧栏和移动抽屉的导航顶部；桌面收起态不塞入不可用的小输入框，用户先用现有收起按钮展开。
- 空查询显示正常分组导航；有查询时在同一滚动区域显示匹配链接，避免绝对定位浮层被侧栏裁切。
- 匹配采用 trim + lowercase + `includes`，数据量小于几十项，无需模糊算法、服务端接口或新依赖。
- 结果显示目标名称和所属页面；无结果用 `role="status"`，结果数量用 `aria-live="polite"`。
- 结果是普通 `<Link>`，Tab/Enter 使用浏览器原生行为；Escape 只负责清空查询。不实现自定义 combobox/listbox 光标状态。

## 5. 共享页面骨架

- 继续复用 `PageHeader`，不新增第二个页面标题组件，也不全局修改其 23 个调用方。
- 十个目标页面统一页头与正文的基础垂直节奏，并为满高 Manager / 宽表格补 `min-w-0`、`min-h-0` 等必要约束。
- 资源管理页保留现有 Manager；配置页保留现有表单；数据页保留筛选、摘要和明细。只修正明确的容器漂移，不把三类页面强行做成同一种卡片。
- 可逆启停统一复用原生语义的 `StatusSwitch`：状态列即操作入口，其他操作仍留在操作列；账号列表没有其他行级动作，因此删除独立操作列。模型路由的有效状态还受服务商状态影响，不与本地路由开关合并。
- 输出样式 Manager 默认只展示管理列表；每行使用独立预览按钮，按需在现有 `Modal` 中展示真实 Markdown 样例及桌面/移动视口切换。
- 共享 `AppShell` 只补影响所有设置页的布局约束，不改变聊天页或其他外壳。

页面落点：

| 类型 | 页面 | 处理原则 |
| --- | --- | --- |
| 资源管理 | 密钥、服务商、模型、指令卡、账号 | 页头、主操作和 Manager 起点一致，保留各自 CRUD |
| 配置/内容 | 联网搜索、长期记忆 | 保持可读宽度，统一保存/错误反馈层级 |
| 数据/监控 | 用量、运维 | 保留筛选和数据密度，避免页面级横向溢出 |
| 复合配置 | 系统设置 | 内部二级导航、单工作区和统一草稿发布反馈 |

### 5.1 指令卡归属

- `instruction_cards.user_id` 改为非空，删除 `scope`；每张卡只能属于一个用户。
- 列表、按 ID 读取和写操作均以当前 `userId` 为资源权限边界，聊天不能通过卡 ID 注入他人的卡。
- 创建/编辑界面删除可见范围和内置只读状态，所有展示卡均可由当前用户管理。
- 迁移保留已有 `user_id` 的卡并删除无法归属的旧卡，不引入系统用户或模板机制。

## 6. 系统设置路由兼容

- 顶层仍使用 `?tab=models|output|governance|protocol`。
- 输出子视图使用 `view=modes|styles`；治理子视图使用 `view=policy|history`。
- 旧值 `basic`、`model`、`output-modes`、`render-styles` 继续解析；后两者分别映射到 output/modes 与 output/styles。
- 现有 `#embedding-model`、`#title-model-id`、`#compact-model-id`、`#mem0-model-id`、`#gateway-user-agent` 等锚点保留。
- range 仅在 governance/history 读取；非历史视图不触发治理分析查询。
- 领域 Tab 继续使用普通 `<Link>` 和移动端原生 `<select>`；子视图使用同样的 URL 驱动方式，不新增客户端全局状态。

## 7. 草稿与发布

- `settings_control_state.current_revision`、草稿 id/version、发布 compare-and-swap、缓存 key 和历史结构完全不变。
- `SettingsChangeControl` 从“常驻右栏卡片”调整为：
  - 无草稿：页面级次要“发布记录”入口，不显示 revision 状态卡。
  - 有草稿：内容区底部可持续访问的轻量状态条，显示待发布变更数、审核并发布、放弃；移动端不遮挡主要内容。
  - 审核与历史继续复用现有 Modal 和人类可读差异组件。
- 常规文案从“当前发布 rN / 已保存”改为“没有待发布更改 / 已保存到待发布草稿”。
- revision 只保留在历史记录、回滚目标和冲突诊断中。

## 8. i18n、无障碍与视觉

- 导航搜索和系统子视图文案同步写入 `en.json` 与 `zh-CN.json`。
- 搜索结果、空态、草稿状态和 Action 错误使用现有状态公告模式。
- 所有新增交互提供 `focus-visible`；直接实现的紧凑控件接入 `touch-target`。
- 使用现有语义字号、状态色和冷调中性色；静止状态无投影，不增加暗色分支、装饰动效、毛玻璃或彩色侧边条。

## 9. 测试与回滚

- 为导航过滤写一个最小纯函数/组件测试，覆盖页面结果、字段结果、无结果和权限过滤后的输入数据。
- 更新 `SettingsTabs` 测试，锁定搜索移除、旧 alias 与 output/governance 子视图链接。
- 更新 `SettingsChangeControl` 测试，锁定空闲态不展示 revision、有草稿显示准确文案、审核/历史仍可达。
- 为指令卡服务补最小权限测试，并断言迁移删除 scope、收紧 user_id、同步 journal/snapshot。
- 既有 Manager、settings-control 服务与数据库测试不因本次前端重排而改写。
- 回滚按文件组进行：共享导航搜索可独立回滚；系统设置页面/Tab/控制条可独立回滚；页面容器微调可逐页回滚。

## 10. 风险

- 共享侧栏影响十个设置入口，必须分别验证普通用户与管理员拿到的搜索结果。
- `/admin/settings` query 兼容若遗漏会破坏旧书签；解析映射需要单测覆盖。
- 发布控制从右栏移走后，长页面上的待发布状态必须在四档视口检查不遮挡内容。
- 各 Manager 内部布局差异较大；本次不统一其业务结构，避免把视觉重设计扩展成高风险重写。
