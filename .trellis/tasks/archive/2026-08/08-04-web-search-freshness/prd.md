# 联网搜索结构化时效控制

## Goal

让用户明确询问“最新、近期或指定日期范围”时，搜索请求能够使用可验证的结构化时间约束，而不是只依赖提示词或供应商默认排序；普通知识查询保持不限时间。

## Background

- 当前外部搜索公共接口只有 `query`、`maxResults` 和 `signal`，无法表达时效要求。
- Hosted Search prompt 会注入当前 UTC 日期并要求优先近期来源，但这只是模型排序提示，不是工具级时间过滤。
- 搜索结果只保留标题、URL 和摘要，系统无法验证、排序或展示发布日期。
- 外部后端按用户顺序串行尝试，首个非空结果即成功；当前结果缓存键也不包含时间条件。

## Requirements

- `web_search` 工具接受可选的结构化时效参数，普通查询不携带时间约束。
- “最新新闻”语义使用最近 7 天；“近期”语义使用最近 30 天；用户明确日期时使用起止日期。
- 时间语义由主模型通过工具参数表达，不在服务端维护中文关键词匹配规则。
- 搜索服务在单一边界校验日期格式、日期先后关系和时效参数组合。
- 仅向明确支持对应时间能力的搜索后端发送约束；不支持时必须留下可判断的结果，不能静默忽略约束。
- 最近 7 天没有结果或没有可用后端时，允许最多放宽一次到最近 30 天；每轮都按用户配置顺序尝试支持该范围的后端。
- 回退必须在工具结果和 trace 中记录请求范围、实际范围及回退状态，供最终回答明确说明。
- 明确日期范围和最近 30 天请求不得继续无界放宽。
- 缓存键必须包含所有影响结果集的时间条件，避免不同时间范围共用缓存。
- 搜索结果在上游提供日期时保留规范化后的发布日期或更新时间，并将其提供给最终回答模型。
- 现有能力矩阵按已安装版本和官方参数执行：Tavily 支持 7 天、30 天和明确日期；Google Hosted Search 支持转换后的明确起止时间；SearXNG 只参与 30 天范围；Bocha、智谱、OpenAI Hosted Search、Anthropic Hosted Search 和 xAI Hosted Search 暂按不支持硬性时间过滤处理。
- 不新增搜索 provider，不改变用户现有后端顺序，不影响未携带时效参数的搜索行为。
- 不在本次任务中处理每个 `web_search` 调用与 UI 后端标签的逐调用绑定。

## Acceptance Criteria

- [x] 普通查询继续按原有 query-only 路径执行，缓存与回退行为兼容。
- [x] 最近 7 天、最近 30 天和明确日期范围能够从工具参数贯穿到支持它的 provider 或 Hosted Search 请求。
- [x] 非法日期、结束早于开始或冲突参数在发出网络请求前被拒绝。
- [x] 最近 7 天无结果或无可用后端时只执行一轮最近 30 天回退，并在工具结果和 trace 中标明实际范围及回退。
- [x] 其他时效请求无结果时不执行无界搜索。
- [x] 不支持请求时间约束的后端不会静默执行不限时间搜索；有后续后端时继续尝试。
- [x] 不同时间条件生成不同缓存键，相同条件仍能复用缓存。
- [x] 上游提供的日期能经过规范化、搜索上下文和持久化 trace 保留下来；缺少日期时保持可选而不伪造。
- [x] 相关 provider、搜索服务、逻辑工具和历史投影测试覆盖新增契约。

## Out of Scope

- 新增 Brave、Perplexity、Exa 或其他 provider。
- 多 provider 并行聚合、跨源重排或统一质量评分。
- 在设置页增加用户级默认时间窗口。
- 基于自然语言关键词在服务端猜测时间范围。
- 改造搜索后端标签的逐工具调用展示。
