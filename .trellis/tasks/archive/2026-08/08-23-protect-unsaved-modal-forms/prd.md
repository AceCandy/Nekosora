# 保护弹窗未保存表单

## Goal

防止用户在弹窗中编辑持久化表单后，因误点遮罩、按下 Esc、点击右上角关闭或取消而丢失未保存内容。

## Background

- 共享 `Modal` 会将遮罩点击、Esc、右上角关闭和原生 close 事件统一交给调用方 `onClose`。
- `ShareDialog` 已通过表单快照、`requestClose` 和 `ConfirmDialog` 实现未保存保护。
- 现有其他持久化表单弹窗直接关闭，未检查当前值是否与打开时的基线一致。

## Requirements

### R1 保护范围

以下 9 类尚未保护的持久化草稿必须接入未保存确认：

1. 指令卡新增/编辑。
2. 模型新增/编辑。
3. 路由新增/编辑。
4. 供应商新增/编辑。
5. 密钥备注编辑。
6. 密钥批量添加。
7. 输出模式新增/编辑。
8. 渲染样式新增/编辑。
9. 会话重命名。

### R2 关闭入口

- 遮罩点击、Esc、右上角关闭和取消必须经过同一关闭请求。
- 当当前表单与打开时基线一致时，直接关闭，不显示额外确认。
- 当当前表单与基线不一致时，保留当前输入并显示放弃修改确认。

### R3 确认行为

- 选择“继续编辑”时关闭确认弹窗，原表单和已输入内容保持不变。
- 选择“放弃修改”时关闭原表单，再次打开时使用最近已保存值或新建默认值。
- 表单成功保存后按现有流程关闭，不得再弹出放弃修改确认。

### R4 一致性与国际化

- 放弃修改的标题、说明和按钮文案必须使用共享国际化键，不在各业务组件中重复硬编码。
- 现有 `ShareDialog` 的未保存保护不得回归。

## Out of Scope

- 不为文件/图片/错误详情/Mermaid 预览、删除确认、搜索选择器、导航抽屉或即时生效设置添加未保存提示。
- 不处理 Server Action 失败时弹窗过早关闭。
- 不处理 `ModelFormDialog` 关闭后 `catalogId` 残留。
- 不新增页面级 `beforeunload` 或路由离开拦截。

## Acceptance Criteria

- [ ] AC1：R1 列出的每类表单在未修改时，遮罩、Esc、X 和取消均可直接关闭。
- [ ] AC2：R1 列出的每类表单在当前值与基线不一致时，任一关闭入口都只打开放弃修改确认，不立即关闭原表单。
- [ ] AC3：将字段改回基线值后，关闭不再提示。
- [ ] AC4：“继续编辑”保留原表单的全部当前值；“放弃修改”关闭并在下次打开时恢复基线。
- [ ] AC5：成功保存不触发放弃修改确认，现有保存行为保持不变。
- [ ] AC6：现有 `ShareDialog` 未保存测试通过，新增测试覆盖 dirty/clean、继续编辑/放弃修改及共享 `Modal` 关闭入口。
- [ ] AC7：项目前端 lint、typecheck 和相关单测通过。
