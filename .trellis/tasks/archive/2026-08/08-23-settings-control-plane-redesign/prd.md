# 重设计设置控制面

## Goal

将现有平铺的管理设置页升级为面向管理员和开发者的生产级配置控制面：用户能快速找到设置、理解依赖与影响、在应用前验证结果，并清楚知道配置是否已生效。

## Background

- 现有 `/admin/settings` 包含 5 个平级 Tab：基础设置、模型配置、输出模式、输出样式、流量治理，默认进入模型配置。
- 基础设置管理 Chat/网关 User-Agent；模型配置管理 Embedding、标题、摘要和 Mem0 任务模型。
- 输出模式和输出样式分别以 CRUD 表格管理，均支持启停和拖拽排序；输出样式可包含自定义 CSS 或高信任渲染器。
- 流量治理以单 Key/单用户两个 Scope 管理吞吐与月额度，已有单位、数值边界、保存中和成功/失败反馈。
- 项目已有全局管理侧栏；新设置导航必须避免与 App Shell 形成笨重的双重侧栏。
- DEEIX 仅作为设置壳、统一字段行和视觉预览的参考；不复制其消费级设置信息架构。
- 设计必须继续遵循「星云纯白」单亮色主题、管理侧莫兰迪中性视觉、静止无投影和无装饰性动效的规范。
- 当前持久化跨越 `system_settings`、`output_modes` 和 `render_styles`；治理策略是 `system_settings` 中的单个 JSON 值。
- 当前 `system_settings` 多键保存是逐键写入且没有统一事务；输出模式/样式排序已有局部事务。
- 当前生产代码没有通用设置审计日志、历史快照、单调 revision、基于 revision 的冲突检测或设置回滚入口。
- 输出模式/样式当前使用物理删除；如果进入可回滚变更集，删除结果也必须可由历史恢复。
- 当前用户表对 `role = 'admin'` 设有部分唯一索引，从数据库层保证全局只有一个管理员；本任务不引入多管理员实时协作。
- 当前治理持久化表可提供当前速率桶状态、活动并发租约和当月额度的已用/预留值；现有用量明细只查询成功计费行。
- 当前 Prometheus 指标与数据库均没有可供设置页查询的治理拒绝历史、近期峰值或策略变更影响聚合；这些数据不能从成功请求近似推导。

## Requirements

### R1. 统一信息架构

- 以「模型与任务 / 输出体验 / 流量治理 / 网关协议」重组现有设置，不丢失任何已有配置能力。
- 桌面端提供稳定的局部设置导航，移动端提供可发现、不依赖隐藏滚动条的分类导航。
- 提供设置搜索，可通过用户语言定位到字段或功能，无需先记住所属分类。

### R2. 统一配置交互

- 统一设置行、表单控件、保存中、保存成功、保存失败、禁用和校验反馈。
- 所有可修改配置都必须表达当前值、默认/继承来源和实际生效值。
- 高风险操作必须在应用前表达影响范围，不能仅依赖一次性 Toast。
- 所有核心操作支持键盘和触摸；排序不能只有指针拖拽路径。

### R3. 模型与任务矩阵

- 在同一视图中呈现 Embedding、标题、摘要和 Mem0 任务的模型、自动/继承来源和当前状态。
- 对具备可运行路径的任务提供就地测试，测试不得更改当前生产配置。

### R4. 输出体验工作室

- 在同一工作区内清晰区分「输出模式改变模型行为」与「输出样式改变渲染外观」。
- 输出模式提供最终指令预览；输出样式使用真实 Markdown 内容提供桌面/移动实时预览。
- 自定义 CSS 和高信任渲染必须明确呈现安全边界与影响范围。

### R5. 流量治理控制面

- 保留现有单 Key/单用户 Scope、单位、数值范围和默认值行为。
- “单 Key/单用户”表示现有策略的两种聚合 Scope，不新增按某个具体 API Key 或用户筛选历史的能力；持久化趋势只展示各 Scope 的整体计数和高水位。
- 在可靠数据来源存在时，就地呈现近期实际峰值、限制命中或变更影响；不得用伪造数据或无依据估算填充。
- 新增持久化的治理小时级聚合数据，至少覆盖请求吞吐峰值、并发峰值、限流/并发/额度拒绝次数与拒绝原因。
- 治理聚合只保存展示趋势与影响所需的数字，不保存请求内容、API 密钥、密钥指纹或可还原单个请求的事件明细。
- 治理聚合采集失败或延迟不得改变原请求的准入、429 拒绝或结算结果；页面必须显示聚合数据的新鲜度。
- 策略影响对比必须基于持久化聚合数据和待应用策略确定性计算，并明确标识为历史回放/预测，不得表达为未来保证。

### R6. 兼容与品牌约束

- 保持管理员权限边界、现有配置值、国际化、数值校验和服务端安全校验语义。
- 支持项目当前的桌面与移动视口，满足 WCAG AA，且不新增暗色模式。
- 管理工作区不使用品牌门面的光晕、星点、流星或编排式入场动效。

### R7. 服务端变更集与回滚

- 统一变更集覆盖本设置控制面的全部系统设置：User-Agent、Embedding/后台任务模型、流量治理策略，以及输出模式/样式的新增、修改、启停、删除和排序。
- 配置变更集、版本历史和回滚必须由服务端持久化与执行，不得仅存在于前端草稿状态。
- 应用变更时必须保存变更前后的可审查记录，并记录操作者与时间。
- 回滚必须通过新的服务端变更恢复历史状态，不覆写或删除原有历史记录。
- 回滚指定历史发布时，只根据该次发布记录的完整前后值生成反向差异，不将全部系统设置恢复到历史时间点。
- 反向差异作为新的活动变更集生成，必须经过正常差异审查、冲突检测与原子应用；如果后续版本已修改同一设置，不得静默覆盖较新值。
- 变更集必须在应用前完成权限检查、服务端校验与冲突检测，不得信任前端提交的差异结果。
- 变更集应用不能复用当前非事务的多个 server action 串行写入；服务端必须提供明确的一致性边界。
- 同一变更集必须整批原子应用：所有变更先通过服务端校验与冲突检测，再在一个数据库事务中全部写入；任意一项失败时生产配置全部保持原状。
- 业务缓存失效和运行时客户端重置只能在数据库事务成功提交后统一触发，不得于事务中造成不可回滚的进程外副作用。
- 草稿变更集与历史记录仍保存操作者 ID，但不新增多管理员共同编辑、审批或实时协作语义。
- 单管理员始终最多只有一个活动变更集；首次修改时自动创建并持久化，只有应用或放弃后才能开始新的变更集。

## Acceptance Criteria

- [ ] 现有 5 个 Tab 中的每一项配置都能在新信息架构中被定位和操作，无功能丢失。
- [ ] 管理员可从设置导航或设置搜索到达模型任务、输出体验、流量治理和 User-Agent 配置。
- [ ] 每种保存操作都有可见的进行中、成功或失败状态，失败时不丢失用户输入。
- [ ] 模型与任务视图可直接识别每个任务的显式模型、自动选择或继承来源。
- [ ] 输出模式可预览指令，输出样式可使用真实 Markdown 内容切换桌面/移动预览。
- [ ] 流量治理保留全部现有 Scope、单位、范围校验和默认回退，且仅展示有可靠来源的运行影响数据。
- [ ] 治理页可查看持久化的小时级吞吐峰值、并发峰值和各类拒绝数，页面重启或进程重启不丢失已聚合历史。
- [ ] 治理聚合记录不包含请求内容、API 密钥、密钥指纹或单请求明细。
- [ ] 聚合刷新失败不会把本应成功或返回 429 的请求改成 503，页面可识别数据延迟而不会把旧数据伪装成实时值。
- [ ] 修改治理策略后，应用前页面可用历史聚合数据对比现策略与待应用策略的限制影响，并明确告知这是历史回放而非未来承诺。
- [ ] 桌面和移动视口均不出现不可达操作或表格裁切，核心流程可仅使用键盘完成。
- [ ] 视觉与动效符合 `DESIGN.md` 的单亮色、稀有主色、静止无投影和管理界面动效限制。
- [ ] 管理员可创建服务端持久化的变更集、审查配置差异并一次应用，页面重载或换设备后草稿仍然存在。
- [ ] 同一变更集可同时包含 `system_settings`、输出模式和输出样式变更，并使用同一套差异审查、应用、历史和回滚语义。
- [ ] 输出模式/样式的删除与排序变更均进入历史，并可通过新变更回滚。
- [ ] 每次应用都生成不可静默改写的历史记录，包含操作者、时间和变更前后状态。
- [ ] 管理员可将指定历史版本作为新变更回滚，且原始历史和回滚操作均可审查。
- [ ] 反向撤销某次发布时只反转该次修改过的字段、实体和顺序，不改动之后版本中与它无关的配置。
- [ ] 如果要撤销的设置已被后续版本再次修改，系统必须显示冲突并阻止静默覆盖。
- [ ] 并发管理员修改了同一配置后，过期变更集不会静默覆盖较新值。
- [ ] 变更集中任意一项校验、冲突检测或数据库写入失败时，所有生产配置、版本记录与排序均不发生部分更新。
- [ ] 变更集仅在数据库事务成功提交后触发相关业务缓存失效与运行时重置。
- [ ] 首次修改任意系统设置时自动创建唯一活动变更集，后续修改合并到该草稿，页面重载后仍可继续编辑。
- [ ] 存在活动变更集时不能再创建第二个草稿；应用或放弃后活动草稿清空。

## Out of Scope

- Chat 主页的对话布局与消息渲染改版。
- 与设置控制面无关的模型目录、路由、计费、账户或订阅业务改造。
- 为了填满界面而新增伪造运行数据或与当前设置无关的指标。
- 审计级零损失的单请求治理事件账本或专用遥测管道；本任务只持久化有界刷新后的聚合数字。

## Key Decisions

- 变更集、版本历史与回滚采用真实服务端持久化与执行，不做仅前端模拟的实现。
- 统一变更集覆盖全部系统设置，不保留绕过变更集的输出模式/样式即时 CRUD 路径。
- 同一变更集采用单一数据库事务整批原子应用，不允许按设置领域部分成功。
- 依据当前数据库约束，本任务按单管理员产品设计，不扩展管理员数量或引入协作审批流。
- 单管理员最多只保留一个活动变更集，不支持多个命名草稿。
- 回滚采用「反向撤销指定发布」，不采用全量历史快照恢复。
- 流量治理新增持久化小时级聚合采集，用于历史趋势与策略影响回放；不只使用当前实时/月度状态。
- 聚合采用不阻塞准入热路径的 5 秒目标批量刷新，固定保留 90 天；异常进程退出可能损失尚未成功持久化的缓冲，已持久化历史不受重启影响。

## Notes

- 本任务是复杂任务；`design.md` 和 `implement.md` 已补齐，方案已确认并进入实现。
- 设置变更历史不复用聊天消息软删除或 Artifact 版本链；它们仅能作为局部持久化模式参考。
- 如果未来移除单管理员唯一约束，多人冲突、审批和草稿协作需作为新需求重新设计，不在本任务预留接口。
