# 修复流式搜索超时与工具轮正文

## Goal

让 Hosted Search 在已经正常流式返回时不被固定总时长误杀，并确保搜索成功后的最终回答只包含可读总结；搜索尝试链必须准确区分真正不可用与此前超时后的主动跳过。

## Background

- 当前 Hosted Search 使用 `generateText()`，必须完整结束后才能返回；统一 10 秒后端超时会中断已开始生成但尚未完成的请求。
- `searchWeb` 的固定 30 秒信号同时中止当前尝试和后端回退，无法表达“首包按时到达后继续等待完成”。
- Agent 工具轮的 `text-delta` 会立即进入 SSE、前端正文和服务端持久化；同轮随后调用工具时，查询计划或关键词不会被撤回。
- 超时后共享 Map 会让同一回答的其他搜索跳过该后端，但 trace 仍记为 `unavailable`，界面无法区分“此前超时后跳过”和真正不可用。

## Requirements

- Hosted Search 使用 AI SDK 流式事件消费，同时保留最终摘要、来源和用量。
- Hosted Search 等待首个有效上游进度的上限为 30 秒；本地 `start` 事件不算有效进度。
- 收到文本、推理、来源或 Hosted 工具进度后，取消首包计时并使用 30 秒流中空闲超时；每次有效进度重置空闲计时。
- 流持续产生有效进度时不设置完成硬上限，等待其自然完成；调用方取消始终立即中止。
- 搜索回退窗口为 60 秒，只决定是否继续启动后端。窗口到期不得中断已开始返回的 Hosted 流；若该流随后失败且窗口已耗尽，则停止继续回退。
- 外部搜索 Provider 继续使用单后端 10 秒超时，并受回退窗口剩余时间约束。
- 模型在一个工具轮中先输出正文、随后发出工具调用时，撤回该工具轮已输出的正文；普通无工具回答继续实时流式展示。
- 正文撤回必须同时更新 Core 聚合正文、内部 Chat SSE、前端待刷新 delta 缓冲和消息正文，刷新后不得恢复被撤回内容。
- 正文撤回只移除当前工具轮的精确后缀，继续生成已有正文不得被清空。
- 超时后主动跳过使用独立尝试结果 `skipped_after_timeout`，界面显示“已跳过（此前超时）”；真正不可用继续显示“不可用”。
- 保持用户后端顺序、最多三条并行搜索、周到月回退、Hosted 可读模型名称和公开 `/v1/*` 协议不变。

## Acceptance Criteria

- [ ] Hosted Search 在 30 秒内无有效上游进度时中止并继续后端回退。
- [ ] Hosted Search 在 30 秒内开始返回且后续间隔均小于 30 秒时，即使总耗时超过 60 秒也能完整成功。
- [ ] Hosted Search 开始返回后连续 30 秒无进度时中止；外层取消仍立即终止。
- [ ] 回退窗口内 Hosted Search 失败后继续 Tavily；窗口已耗尽且 Hosted 流失败时不再启动新后端。
- [ ] 外部 Provider 仍在 10 秒超时并继续后端链。
- [ ] 工具调用前的搜索计划/关键词可以短暂流式显示，但工具轮确认后会被撤回，最终正文和持久化正文均不包含它。
- [ ] 普通无工具回答保持逐 token 流式输出；继续生成不会删除已有正文。
- [ ] 同一回答后续搜索显示 `已跳过（此前超时）`，不再误显示为 `不可用`；历史恢复与实时状态一致。
- [ ] Tavily 成功后主模型输出自然语言总结，引用来源仍可用。
- [ ] Core/Web 定向测试、类型检查、lint 和相关完整测试通过。

## Out of Scope

- 不为未声明 Hosted Search 能力或协议不兼容的模型伪造搜索能力；`step-3.5-flash` 此类路由仍按不支持处理。
- 不改变搜索模型目录能力判定、用户配置或数据库表结构。
- 不保证第三方服务在收到取消后立即停止服务端计算。
- 不修改公开 OpenAI 兼容流协议；内部正文撤回事件只用于 WebChat。

## Risks

- 持续有进度的 Hosted Search 可以超过 60 秒，这是用户明确选择的正确性优先行为；仍由空闲超时和用户取消兜底。
- 旧 WebChat 客户端不认识正文撤回事件时仍可能显示临时文本；同仓 Core 与 Web 必须同步发布。
