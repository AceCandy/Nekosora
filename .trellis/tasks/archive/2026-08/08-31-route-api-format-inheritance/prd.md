# 路由默认继承服务商协议

## Goal

减少模型路由配置中的重复选择：路由默认使用所选服务商协议对应的上游 API 格式，同时保留高级覆盖能力。

## Background

- 服务商的 `protocol` 负责连接类型、默认地址、模型列表拉取和部分 SDK 选择。
- 路由的 `apiFormat` 决定具体模型请求使用 Chat Completions、Responses、Anthropic Messages 等 wire format。
- `routes.api_format` 当前为非空字段，运行时直接读取；本次保留该契约，只优化表单默认值与信息层级。

## Requirements

- 新增路由选择服务商后，使用现有 `defaultRouteApiFormat()` 自动生成 `apiFormat`，普通流程无需再次选择。
- 路由表单将 API 格式选择器降级到原生、可访问的高级设置区域；聊天模型允许显式覆盖默认格式。
- 编辑已有非默认格式的路由时，高级设置默认展开，避免隐藏已生效的覆盖值。
- 表单始终提交当前 `apiFormat`；保留现有服务端校验、数据库非空约束和运行时行为。
- 保留现有语义：用户显式选择 API 格式后再切换服务商，不自动抹掉该覆盖值。

## Acceptance Criteria

- [x] 新增聊天路由时，选择服务商即可提交默认 API 格式，不需要操作高级设置。
- [x] 打开高级设置后，可以选择并提交其他聊天 API 格式。
- [x] 编辑默认格式路由时高级设置默认收起；编辑非默认格式路由时默认展开并回显原值。
- [x] 非聊天模型不显示无意义的 API 格式覆盖控件，但仍提交由服务商协议派生的合法格式。
- [x] 不新增数据库迁移、后端分支或第三方依赖。
- [x] 相关前端静态检查和最小行为测试通过。

## Out of Scope

- 服务商协议修改后，自动批量重写已经保存的路由格式。
- 调整服务端允许的协议/格式组合或数据库结构。
- 重构模型、服务商管理的其他表单。
