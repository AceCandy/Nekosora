# 加固模型拉取、RAG 来源与离线预检

## Goal

以三个可独立验收、可分别回滚的改动，提高 Provider 配置安全性、RAG 回答可追溯性和聊天在明确离线时的失败体验。

## Background

- 上游模型列表由 `fetchUpstreamModels` 统一拉取，但目前会全量执行 `Response.json()`，没有响应体和模型数量硬限制，并默认跟随重定向。
- 附件 RAG 已保留 `fileId`、`filename`、`chunkIndex`、`content` 和 `similarity`，但 `buildRagContext` 只把文本拼入 system 消息，来源信息没有进入最终消息契约。
- 浏览器端没有统一离线请求边界；聊天流和附件上传仍会在 `navigator.onLine === false` 时发起请求，侧栏分页已有单点预检。
- 父任务只负责三个子任务的共同范围、顺序和最终集成复核，不直接承载业务代码修改。

## Requirements

- R1：加固上游模型列表拉取，限制资源消耗和凭据跨域传播，同时保持现有 Provider 超时、错误脱敏与旧缓存保留语义。
- R2：为现有全文和向量附件 RAG 增加文件级结构化来源；私有会话支持属主鉴权预览，匿名分享完全隐藏来源。
- R3：为聊天 JSON/SSE 请求和附件上传增加明确离线预检，不扩展为 PWA 离线缓存或通用请求框架。
- R4：三个子任务分别规划、实施、测试和回滚；集成复核确认共享类型、错误语义和隐私边界没有互相破坏。

## Acceptance Criteria

- [ ] 三个子任务均通过各自验收标准和最小定向测试。
- [ ] 上游模型拉取的超限或非法重定向不会覆盖已有缓存，也不会泄露 API key。
- [ ] RAG 来源在私有会话生成完成后立即可见，刷新后保持一致，匿名分享不泄露私有文件标识或入口。
- [ ] 浏览器明确离线时，聊天发送、重试、编辑重发、续写和附件上传均不调用 `fetch`，恢复在线后可正常重试。
- [ ] 不新增第三方依赖，不新增数据库迁移，不改变模型目录、路由、分享和附件鉴权的既有事实来源。

## Out of Scope

- 团队工作空间、持久沙箱、支付/credits、工具预算和长会话窗口化。
- 通用离线模式、Service Worker 缓存、请求排队或自动重放。
- 独立 RAG provenance 表、匿名分享文件下载协议或知识库产品化。
