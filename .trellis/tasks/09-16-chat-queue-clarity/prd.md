## 验收条件

- 生成期间，在用户按回车前明确提示将加入待发送队列。
- 队列显示待发数量及采用实际发送时模型与设置的规则。
- 排队仅发送文本；输入区附件保留，普通主动发送仍能提交附件。
- 明确停止当前回答对队列的影响；未收到暂停方案确认时保留现有继续发送语义，并在停止按钮和队列中说明。
- 修复旧请求延迟收尾清空下一条请求运行态的竞态，覆盖全部四种生成动作。
- 覆盖入队、发送配置、附件隔离和选定的停止行为，完成项目检查与浏览器验证。
- 新会话自动建会期间不得因侧栏后台轮询刷新重挂输入组件，待发队列与草稿必须保留。

保留上一任务未提交的改动。本任务不改变模型目录、网关协议、跨页面队列持久化或聊天排版。

## 丢队列修复

- 最终范围为 Sidebar 生成状态轮询及分组摘要、createConversation 的刷新边界、对应回归测试和规范；不迁移队列到全局 store，不改变主动切换会话时的本地状态生命周期。LoginForm 试验改动及其临时测试已全部撤回。
- Sidebar 原先在轮询返回空或某个 run 完成时整页刷新；新会话 History URL 已切到真实 ID 后，这条路径会重挂 Composer。现改用已有局部状态更新，SSR 初始生成列表只在新导航快照到来时采用，避免旧值导致轮询无法停止。
- 回归测试先断言旧代码错误调用 refresh 而失败，修复后通过；新增覆盖本地生成早于服务端 run、服务端结束后收敛、轮询失败重试与 cleanup、新 RSC 快照接续。
