## 反模式判定 (Anti-Patterns Verdict)

### 智能体评估 (LLM Assessment)
- **色彩与边框混杂**：虽然整体色调符合「暮色微澜黑与星云纯白」策略，但由于大量原生 HTML 边框颜色（如 `border-neutral-200` / `dark:border-neutral-800`）的混入，使得某些组件边缘的视觉强度在深/浅色模式切换时产生了微妙的偏差，没有完全达到设计规范中“天空般的开阔与治愈”的透气感。
- **组件撕裂**：在 `ProviderFormDialog` 中，没有使用定义好的 `Input`、`Select` 和 `Button` 组件，而是为了图省事而硬编码了一套几乎一模一样但细节不同的 inline 样式。这是非常典型的 AI 编程反模式——“复制粘贴的样式繁衍”。

## 整体印象 (Overall Impression)
项目的前端框架非常扎实，已经初步建立了基于 OKLCH 的颜色主题（暮色微澜黑与星云纯白）和组件基础（Button、Input、Select、Modal）。然而，各页面与组件在实际编码时，没有做到 100% 遵守设计系统 Token，产生了多处“野生的”硬编码样式与重复按钮样式。只要消除这些一致性死角，整个平台的视觉精致度就能实现大幅跃升。

## 优秀设计点 (What's Working)
- **优秀的扁平化设计与零投影原则**：静止状态下的卡片、表格均无阴影，主要靠极细的边框进行区域划分，高度契合「零影子原则」。
- **强大的原生 Dialog 弹窗**：`Modal` 基于原生 `<dialog>` 实现，天生自带焦点陷阱（Focus Trap）和 ESC 键退出，符合高水准的交互标准。
- **严谨的系统字体栈**：没有滥用花哨的英文字体，系统 Sans-serif 字体在表格与表单中的对齐感极强，非常符合 `product`（设计服务于任务）的注册定位。

## 优先修复的问题 (Priority Issues)
- **[P1] 一致性缺陷：后台管理页与通用弹窗未采用设计系统 Token**
  - **Why it matters**: `AdminLayout`、`AdminHomePage`、`Modal` 等核心后台页面和组件大面积硬编码 `neutral-200`、`neutral-800` 等边框与背景色，导致页面在切换深色模式时，边框对比度不一致，破坏了“暮色微澜黑”与“星云银”的纯净色彩质感，与已使用 Token 的 `PanelLayout` 形成强烈撕裂感。
  - **Fix**: 将这些区域的硬编码边框与背景替换为 `border-morning-mist`、`dark:border-deep-space` 和 `bg-nebula-white` / `dark:bg-twilight-obsidian`。
  - **Suggested command**: `$impeccable layout`
- **[P1] 一致性缺陷：表单控件未复用标准 UI 组件**
  - **Why it matters**: `LoginPage`、`ProviderFormDialog`、`KeyBundleEditor` 直接使用原生的 `<input>` 与 `<select>` 并硬编码样式（如 `inputCls`），而非复用项目里已有的 `<Input />` 和 `<Select />` 组件。这破坏了交互规范的单一可控性，且容易在后续的焦点环、提示状态等扩展中产生遗漏。
  - **Fix**: 重构这些表单，将原生的 `<input>` 和 `<select>` 统一替换为项目内定义的标准 UI 组件。
  - **Suggested command**: `$impeccable polish`
- **[P1] 一致性与体验缺陷：弹窗动作按钮采用硬编码样式而非标准按钮组件**
  - **Why it matters**: `ProviderFormDialog` 底部的“取消”和“创建/保存”按钮采用硬编码的 tailwind 样式，而不是使用统一的 `<Button>` 组件。这导致按钮的 Hover、Focus 态行为和品牌 Sora Blue 的 `Orbital Hover` 阴影无法自动继承，破坏了按钮交互体验的一致性。
  - **Fix**: 使用 `<Button variant="secondary" size="sm">取消</Button>` 与 `<Button variant="contrast" size="sm">创建/保存</Button>` 替换硬编码按钮。
  - **Suggested command**: `$impeccable polish`
- **[P2] 易用性缺陷：侧边栏导航未绑定设计系统 Sora Blue 高亮**
  - **Why it matters**: 无论是 `SidebarNav` 还是 `AdminSidebarNav`，高亮激活项使用的是 Tailwind 默认的 `bg-blue-50 text-blue-600 dark:bg-blue-950/20`，与项目品牌色 `sora-blue` (天空蓝) 存在轻微的色相撕裂，且背景色不够柔和（规范要求 rgba(59, 130, 246, 0.08) 即 `bg-sora-blue/8`）。
  - **Fix**: 更新激活态样式，使用 `text-sora-blue bg-sora-blue/8` 代替默认的 blue 颜色类。
  - **Suggested command**: `$impeccable colorize`
- **[P2] 无障碍与美观缺陷：辅助提示字体过小且使用非规范 Emoji**
  - **Why it matters**: `KeyBundleEditor` 底部说明文字使用了 `text-[10px]`，在低分辨率或视力不佳的屏幕上极难阅读；同时使用 `💡` 和 `✕` 等偏向娱乐的 Emoji/字符作为提示与关闭按钮，不够严肃和工业化。
  - **Fix**: 将辅助文本字号调整为 `text-xs`，替换 Emoji 为更规范的排版，或用轻量图标代替；将 Modal 关闭按钮的 `✕` 替换为标准的 Lucide `X` 图标。
  - **Suggested command**: `$impeccable typeset`

## 角色体验红线 (Persona Red Flags)
- **Alex (资深用户)**: 没有键盘快捷键支持。在管理后台中，从上游配置面板跳转到用户密钥面板，或者在多个 Provider 之间切换时，必须要通过鼠标点击侧边栏。无法使用 `Cmd+K` 或快速按键切换，大大降低了资深开发者的操作效率。
- **Jordan (新手用户)**: 在 `ProvidersManager` 中，API 密钥的“权重”输入框只有一个数字输入框，缺少权重在多 API Key 随机选用中如何起作用的清晰文字指引（虽然底部有注释，但字号过小容易被忽略）。
- **Sam (无障碍依赖用户)**: `KeyBundleEditor` 的提示文字只有 `text-[10px]`（约 7.5px），不仅字号过小违背 WCAG 规范，且在深色模式下与 `neutral-500` 的对比度偏低；另外，部分输入框的 `:focus-visible` 焦点状态没有统一的 Sora Blue 高亮外发光环，导致键盘导航时的焦点位置难以辨认。

## 次要观察项 (Minor Observations)
- `AdminLayout` 中的管理员邮箱排版较密，可以增加一点行距以保证视觉呼吸。
