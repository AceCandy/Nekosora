# 星枢界面与体验审视

我的判断：美观已有基础，交互细节仍需补齐，易用性的提升空间最大。下一版应让用户打开就能开始任务、选择模型时有依据、配置网关时每一步都知道是否成功。

冷白底色、文字为主的聊天正文、克制的欢迎区都值得保留。当前的主要短板集中在能力的组织与解释：重要入口较隐蔽，部分页面先展示系统有什么，再让用户寻找自己要做的事。

## 值得保留的优点

- 聊天区以阅读和输入为中心，没有堆积无关模块；16px 输入文字与宽度受控的正文适合持续使用。
- 聊天和管理页已有区别：前者留白充分，后者使用表格承载资源信息，这个方向成立。
- 搜索、侧栏折叠、部分快捷键、减弱动效、焦点样式、配置草稿与发布确认已有基础。模型弹层的 Escape 关闭与焦点返回已实测成立。

## 五项优先改进

### 1. P1：把网关接入组织成一条完整任务

聊天侧的管理入口位于头像菜单；管理侧将密钥、服务商、模型分别组织为页面。添加服务商时，协议、检测模型、三项超时和密钥编辑同时出现。熟悉系统的人能完成配置，新用户需要先理解系统的对象关系。

我建议在聊天侧提供可见的「网关控制台」入口。网关内围绕「接入资源、运行记录、系统管理」分组，并明确个人资源与全局设置的作用范围。

首次接入围绕这条任务组织：填写上游地址与密钥 → 选择模型并建立路由 → 查看测试结果 → 开始聊天或取得调用示例。已有完整配置页继续服务熟练用户。检测模型、超时、权重等进入可展开的高级设置，配置摘要保持可见。

图像页目前在无模型时会显示说明，不能认定为“页面没有内容”。实际问题是文案直接出现 `capabilities.imageGeneration`，没有配置入口。应改为「还没有可用的图像模型」，并按权限提供「配置图像模型」入口或联系管理员的说明。

验收：新用户无需寻找第二份说明即可接入第一个模型；每个缺配置状态都说明缺什么、去哪里完成；熟练用户仍可直接访问高级配置。

证据：[管理入口](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/chat/components/Sidebar.tsx:873)、[导航组织](/vol1/1000/ssd/workai/Nekosora/apps/web/src/shared/nav-config.ts:49)、[超时字段](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/providers/ProviderFormDialog.tsx:305)、[图像空态](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/image/ImageStudio.tsx:99)、[图像文案](/vol1/1000/ssd/workai/Nekosora/apps/web/messages/zh-CN.json:1352)。对应工作：`impeccable shape`、`onboard`、`clarify`。

### 2. P1：让用量页先回答用户的问题

在本次没有调用记录的数据状态下，1440×1000 的首屏几乎被统计卡和空图表占满；时间范围、筛选、错误请求与明细位于下方。当前总览虽然可折叠，默认展开仍使查询路径变长。

建议将页面顺序调整为：时间与对象筛选 → 紧凑摘要 → 请求明细／错误请求 → 可展开图表。全时间累计与所选时间范围必须明确区分。没有数据时，用一个清晰空态说明当前范围、筛选条件和下一步，压缩多个重复的空图表。

网关管理表也应突出可用性：资源名称、启用状态、检测结果及检测时间组成首层摘要；协议、完整 URL、逐密钥结果与低频操作进入详情。检测时间可以防止用户把上次检测结果理解为实时状态。

验收：首屏可以选择时间、查看记录或切换错误请求；无数据时可分辨“尚未使用”和“筛选无结果”；资源状态能看出检测时效。

证据：[总览先于明细的布局](/vol1/1000/ssd/workai/Nekosora/apps/web/src/app/(dash)/panel/usage/page.tsx:86)、[服务商表格](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/providers/ProvidersManager.tsx:472)。对应工作：`impeccable layout`、`distill`。

### 3. P1：为手机重新组织操作结构

393px 窄屏中，服务商表格约 827px 宽，滚动容器约 359px 宽；首屏主要显示名称与接口地址，状态和操作位于横向滚动之外。上方多个筛选框挤在一排，提示文字被截断。

聊天输入器在手机上也将文本、附加功能、模型和语音挤在同一行，当前模型名会被截断。

建议管理页在手机上以「名称＋状态＋详情入口」作为每行第一层，详细字段展开查看；筛选收为一个带已选数量的入口。聊天输入器采用两层结构：上层完整留给输入，下层放附件、模型与发送；模型设置使用便于操作的面板。

验收：窄屏无需横向寻找主要操作，筛选条件完整可读；输入时能确认当前模型。还需补做真机软键盘、安全区域、触控目标与缩放验证。

证据：[服务商滚动容器](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/providers/ProvidersManager.tsx:472)、[输入器控件占位](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/chat/components/ChatInputBox.tsx:228)。对应工作：`impeccable adapt`。

### 4. P2：让模型选择提供判断依据

当前选择器有搜索，但二十多个选项主要呈现型号名；推理档位用一个小型滑杆表达。用户能找到已经知道名字的模型，却难以据此判断哪些模型适合当前输入。

建议默认展示少量常用或最近使用模型，全部模型仍可搜索，并按厂商或明确的来源分组。每个选项展示已有目录能够证明的能力，例如图片输入、工具调用、推理支持；性能或质量排名只有存在可靠数据时才展示。

推理强度以明确的离散档位呈现，解释其可能影响思考程度与等待时间。显示多少档位仍严格服从具体模型目录，不统一硬编码为三档。

实测搜索框 Tab 进入第一个模型后，ArrowDown 不移动到下一项；Escape 则可关闭并恢复焦点。应补齐列表的方向键导航，并让屏幕阅读器理解当前位置与选中状态。

验收：用户能根据能力选择模型；熟练用户可以用键盘完成搜索、选择和关闭；不显示目录未证实的能力。

证据：[模型选择器](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/chat/components/ChatToolbar.tsx:318)、[选项交互](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/chat/components/ChatToolbar.tsx:413)。对应工作：`impeccable shape`、`harden`。

### 5. P2：用视觉层级与清晰文案提升精致度

我会保留冷白底、深墨文字和天空蓝，进一步强化各自职责：侧栏更安静，输入区更突出，主行动明确。欢迎区可以适当缩小重复的品牌展示，把注意力交还给输入与真实任务示例。

模型管理页重复出现蓝色模板标签、蓝色启用开关和蓝色路由操作；信息虽整齐，却缺少主次。模板名称可回归普通文字，状态采用克制且明确的表现，删除等低频操作收进更多菜单。管理正文维持清晰的 14px 层级，12px 只承载辅助信息，并保证可读对比度。

文案需要同样的整理：「输出模式／输出样式」明确区分为「回答方式／阅读样式」；实际进入待发布草稿的「保存」写成「保存草稿」；「全局渠道」「BYO」等术语与当前导航、目标用户的理解保持一致。已存在的发布确认应保留。

动效集中表达发生了什么：打开、选择、保存、生成、取消。让用户立即知道操作结果，比继续增加装饰性动效更有价值。

验收：重要文字在实际背景上满足 4.5:1；用户能区分待发布与已生效；首次看到两个输出选项就能理解它们的作用。

证据：[导航选中色](/vol1/1000/ssd/workai/Nekosora/apps/web/src/shared/components/SidebarNav.tsx:182)、[推理状态文字](/vol1/1000/ssd/workai/Nekosora/apps/web/src/features/chat/components/ChatToolbar.tsx:392)、[草稿发布控制](/vol1/1000/ssd/workai/Nekosora/apps/web/src/app/(dash)/admin/settings/SettingsChangeControl.tsx:178)、[系统配置文案](/vol1/1000/ssd/workai/Nekosora/apps/web/messages/zh-CN.json:668)。对应工作：`impeccable clarify`、`typeset`、`polish`。

## 不同用户最容易遇到的阻力

- 初次接入者：先找管理入口，再理解服务商、模型与路由的关系；无图像模型时没有直达配置入口。
- 高频聊天者：在长型号列表中重复寻找，推理档位的意义不够直观。
- 键盘用户：模型列表呈现为 listbox，却不能用上下方向键切换；服务商状态筛选缺少名称。
- 手机用户：筛选文字被挤压，重要状态和操作需要横向寻找。
- 排查网关问题的管理员：打开用量页先看到总览，必须进一步滚动或折叠后才进入查询任务。

## 检测结果的取舍

本项目整体不属于明显的模板化界面。问题更集中在后台对象与操作密集、层级不够鲜明，而不是缺少视觉装饰。

静态检测原始结果为 5 条，不能直接当作 5 个缺陷：其中两条来自测试颜色，一条来自 HTML 预览的独立上下文，图片告警命中注释中的 `<img>`，分享按钮告警没有正确考虑 hover 时的文字颜色覆盖。

浏览器覆盖层在聊天、服务商、模型页报告了字体重复、字号比例、布局属性过渡、表格容器及小标签内边距等提示。Inter 和紧凑字号符合工具型界面定位；表格嵌套结构不自动等于卡片滥用；未做性能分析，因此不把布局过渡认定为已经造成卡顿。

已排除的其他误报：图像页并非空白；附件删除按钮并非仅 hover 可见；管理页实际存在 h1；欢迎建议按钮在入场动画结束后复测不再命中对比度问题。选用的回复渲染预设允许与默认聊天样式不同，不把预设特征扩展为全站缺陷。

## 建议的推进顺序

先补齐已确认的交互与可读性缺口；随后围绕首次接入、模型选择、用量排查三条任务设计完整状态与窄屏布局；最后统一视觉与文案。验收以用户能否找到下一步、是否看得清、是否知道操作结果为准。

方案设计时重点检验三件事：首次接入后是否能直接确认可用；任何无数据状态是否给出下一步；控制台首页是否能先回答当前模型和路由是否可用。

本轮用户要求直接给出最佳判断，因此没有追加风格或优先级选择问题。以上是改进建议，尚未改变产品行为。
